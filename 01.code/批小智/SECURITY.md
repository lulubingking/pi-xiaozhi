# 安全与密钥使用约定

## 当前审计结论

- 项目后端不会把网页输入的模型 API Key 写入 SQLite、前端静态资源、审计元数据或 API 响应；它只在当前后端进程内存中使用。
- 审计期间发现的 `OCR工具测试/.env.local` 已从项目中删除；若其中的 Key 曾经被提交、压缩、同步、截图或发到聊天中，仍必须立即在服务商后台撤销并重新生成。
- 旧原型中的 `[已移除的示例密钥]` 是占位字符串，不是可用密钥；它只会造成扫描器误报，不能当作安全凭据。

## 以后每次修改后的检查

```powershell
.\security-audit.ps1
.\security-audit.ps1 -CheckRuntime
```

审计脚本只输出路径和行号，不输出疑似密钥内容。它会检查常见 Key 形态、私钥文件、环境文件、日志以及本地 Key 的精确副本。

## 必须遵守

1. 不要把真实 Key 写入源码、Markdown、截图、测试快照、数据库、导出文件或聊天。
2. 优先使用当前 PowerShell 会话环境变量或隐藏输入；不要使用命令行参数传 Key，避免进入命令历史。
3. 不要重新创建项目内 `.env.local`；即使被 Git 忽略，它仍可能被压缩、备份、云盘同步或恶意软件读取。
4. 生产环境必须使用 HTTPS、明确的 `CORS_ORIGINS`，并把 Key 注入服务端环境或外部密钥管理服务；不要把开发账号暴露到公网。
5. 学生作业图片、OCR 结果和评分数据同样属于敏感数据。`backend/data`、日志和生成的评分快照不要上传到公共仓库或共享盘。

## 首次本地启动

全新数据库首次创建开发教师账号时，在当前 PowerShell 会话中设置 `DEV_TEACHER_PASSWORD`。启动脚本不会打印或写入该密码；已有账号不会被无 Key 的启动脚本重置。
