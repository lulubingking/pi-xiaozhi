## 0. 文档说明

### 0.1 编写目的

本文档将《批小智产品需求文档》和《批小智 UI/UX 设计文档》转换为可执行的研发方案，用于指导：

- 前端页面、路由、组件和交互状态开发；
- FastAPI 后端、数据库和文件存储开发；
- OCR、学生作业归属、客观题判分、主观题评分和教师复核流程开发；
- 前后端接口联调、异步任务处理、异常恢复和报告导出；
- 测试、部署、验收和后续问题定位。

本文档是开发设计文档，不是已经完成的系统实现，也不代表 OCR 准确率、评分一致率、接口可用性或并发指标已经达标。

- `[MUST]`：PRD 明确的首版必须实现或必须验收的要求。

## 1. 产品范围、目标和验收边界

### 1.1 首版必须覆盖的闭环

```text
教师登录
  → 班级和学生维护
  → 创建作业批次
  → 配置题目、参考答案和评分标准
  → 按批次上传 JPG / PNG / PDF
  → 页面拆分和学生多页作业归属
  → 图像预处理与 OCR
  → 教师校对学生、页序、题目和答案
  → 题型分派
  → 客观题规则判分 / 主观题 AI 初评
  → 异常队列
  → 教师查看证据并复核
  → 个人成绩和班级报告
  → PDF 或 Word 导出
```

### 1.2 首版范围

| 范围 | 内容 |
|---|---|
| 学科 | 语文、数学、英语 |
| 题型 | 三类学科的常规题型，具体清单由数据集阶段固化 |
| 输入 | JPG、PNG、PDF；支持批量上传 |
| 识别 | 方向校正、去噪、版面预处理、OCR、文本块坐标、页码和置信度 |
| 评分 | 客观题规则判分；主观题依据评分点、分值和示例作答生成 AI 初评 |
| 复核 | 教师查看原图、OCR、评分依据、AI 建议，修改分数/评语并确认 |
| 报告 | 个人成绩、班级统计、得分分布、高频错误、薄弱项（有真实数据时） |
| 导出 | PDF 或 Word，正式字段与排版待最终交付阶段确认 |
| 运行模式 | 单教师模式；不实现学校级权限、多教师协作和细粒度角色权限 |

### 1.3 明确不承诺

- 不承诺完全替代教师。
- 不把 AI 初评直接作为正式成绩。
- 不把 OCR 失败自动解释为空题。
- 不把相似作答提示自动解释为抄袭或零分。
- 不把原型中的演示数据、模拟分数、测试账号和本地存储作为生产能力。
- 不把 PRD 中的目标准确率、评分一致率、60 秒端到端时间和 4 并发写成已验证结果。

### 1.4 量化目标与验收口径

| 指标 | PRD 目标 | 开发文档处理方式 |
|---|---:|---|
| 印刷体 OCR 字符识别准确率 | ≥95% | 测试集、字符级计算方法、模型和硬件确定后再测量 |
| 工整手写体 OCR 字符识别准确率 | ≥85% | 明确定义“工整”、语言和失败样本处理后再测量 |
| 客观题判分准确率 | ≥99% | 按题型、答案格式、容错规则和逐题分母统计 |
| 主观题评分档位一致率 | ≥85% | 依据人工评分档位、评分人数和仲裁规则统计 |
| 单份作业端到端批改时间 | ≤60 秒 | 同时报告平均值、P95、最大值、重试和人工接管 |
| 单实例后台处理 | 4 个学生作业对象 | 仅作为首版目标，必须在指定硬件和代表性作业集上验证 |

## 3. 业务对象和状态设计

### 3.1 核心对象关系

```text
User
 └── Class
      └── Student

User
 └── AssignmentBatch
      ├── BatchQuestion
      │    └── RubricVersion / ObjectiveRule
      ├── SourceFile
      │    └── SourcePage
      │          └── AssignmentGroup ── Student
      │                └── QuestionAnswerVersion
      ├── GradingRun / GradingTask
      │    └── GradingResult
      │          └── GradingPointResult
      ├── Anomaly
      ├── ReviewRecord
      └── Report / ExportTask
```

### 3.2 批次状态

| 代码 | 中文 | 进入条件 | 允许操作 |
|---|---|---|---|
| `draft` | 草稿 | 批次配置未完成 | 编辑、保存、删除 |
| `uploading` | 上传中 | 至少一个文件正在保存 | 查看进度、等待；禁止重复提交同一批上传 |
| `pending_ocr` | 待识别 | 有成功文件且未启动 OCR | 开始识别 |
| `ocr_processing` | 识别中 | OCR 任务运行 | 查看任务、处理失败项 |
| `pending_correction` | 待校对 | OCR 完成或部分完成 | 进入校对、重试失败页 |
| `pending_grading` | 待批改 | 页面归属和答案均满足校验 | 发起初评 |
| `grading` | 批改中 | 评分任务运行 | 查看任务、有限重试 |
| `pending_review` | 待复核 | 存在未确认的评分或异常 | 进入复核队列 |
| `reviewed` | 已复核 | 所有学生作业题目均已复核且结果未失效 | 查看报告、导出 |
| `partial_failure` | 部分失败 | 部分文件、页面或题目处理失败 | 查看失败项、重试、转人工 |
| `stale` | 待重批 | OCR、答案或评分标准发生影响性修改 | 仅重跑受影响范围 |
| `archived` | 已归档 | 教师主动归档 | 查看历史；禁止新处理 |

`reviewed` 不是单题状态。只有当前学生整份作业的所有题目均完成教师复核、没有未确认归属、没有结果失效时，才允许纳入正式报告。

### 3.3 学生作业对象状态

| 代码 | 中文 | 说明 |
|---|---|---|
| `needs_assignment` | 待归属 | 尚未确定学生或存在候选冲突 |
| `assigned` | 已归属 | 学生和页序已确认 |
| `ocr_pending_review` | OCR 待校对 | 页面已有识别结果但答案未确认 |
| `grading_pending_review` | 评分待复核 | 已生成规则结果或 AI 初评 |
| `anomaly_pending` | 异常待处理 | 存在低置信度、缺页、未匹配等异常 |
| `teacher_confirmed` | 教师已确认 | 当前作业所有题目已复核 |
| `stale` | 结果失效 | 输入、标准或模型配置变化，需要重跑 |

### 3.4 长任务状态

所有上传、OCR、批改和导出任务统一使用：

```text
queued → running → succeeded
                   ├→ partial_failed → retrying → running
                   └→ failed → manual_review / retry

queued / running → cancel_requested → cancelled
```

任务记录至少包含：`task_id`、`task_type`、`batch_id`、`assignment_group_id`、`status`、`stage`、`progress_current`、`progress_total`、`retry_count`、`max_retries`、`error_code`、`error_message`、`created_at`、`started_at`、`finished_at`、`worker_id` 和 `heartbeat_at`。

### 3.5 结果状态

| 代码 | 中文 | 是否进入正式报告 |
|---|---|---:|
| `suggested` | AI/规则建议 | 否 |
| `pending_review` | 待复核 | 否 |
| `teacher_saved` | 教师已保存但未完成确认 | 否 |
| `reviewed` | 教师已确认 | 仅整份作业满足条件时是 |
| `stale` | 已失效 | 否 |
| `failed` | 评分失败 | 否 |

## 4. 数据库设计

### 4.1 数据库通用规则

1. 启用外键：`PRAGMA foreign_keys = ON`。
2. 使用 UTC 或统一的带时区时间格式，接口统一返回 ISO 8601 字符串。
3. 所有可编辑业务对象至少有 `id`、`created_at`、`updated_at`、`version`。
4. 需要停用但不能删除的对象使用 `is_active` 或状态字段。
5. 原始文件和原始 OCR 只读保存，不在更新操作中覆盖。
6. 修改 OCR、答案、评分标准或教师结果时写入历史记录。
7. 所有得分必须能关联到批次、学生、题目、输入版本、评分标准版本和规则/模型版本。
8. 批量写入使用事务；单文件失败回滚该文件事务，不回滚同批次其他文件。
9. 多标签页修改时使用 `version` 乐观锁，版本不一致返回 `409 RESOURCE_VERSION_CONFLICT`。
10. SQLite 首版建议启用 WAL，并对长事务进行拆分，避免任务 Worker 长时间持有写锁。

### 4.11 索引、事务和删除策略

建议索引：

- `assignment_batches(owner_user_id, status, updated_at)`；
- `students(class_id, student_code)`；
- `source_files(batch_id, status)`；
- `source_pages(batch_id, status)`；
- `page_groupings(assignment_group_id, page_sequence)`；
- `question_answers(assignment_group_id, question_id)`；
- `grading_tasks(status, created_at)`；
- `grading_results(assignment_group_id, question_id, result_status)`；
- `anomalies(batch_id, status, severity)`；
- `review_records(entity_type, entity_id, created_at)`；
- `audit_logs(user_id, created_at)`。

事务边界：

1. 创建批次及题目配置：一个事务，失败整体回滚。
2. 单文件上传：文件元数据和文件落盘采用临时文件 + 校验 + 原子改名；数据库提交成功后才标记成功。
3. 单页 OCR：OCR 运行、文本块和页面状态一个事务；原始文件不修改。
4. 保存校对：新答案版本、当前答案指针、失效结果和复核历史一个事务。
5. 教师确认：教师结果、异常处理、复核记录和批次/学生状态一个事务。
6. 报告导出：先生成数据快照，再生成文件；生成失败不改变成绩数据。

删除策略：

- 班级和学生使用停用，不直接删除有历史关联的数据。
- 批次归档后不允许新上传和新评分，但保留历史报告和审计记录。
- 数据清理必须先确认范围，先删除导出缓存和可重建中间文件，再按保留策略处理原始文件。
- 原始文件删除前必须检查是否仍有有效批次、页面、答案或审计依赖。

## 5. 文件存储设计

### 5.1 目录结构

```text
{storage_root}/
├── app.db
├── originals/
│   └── {batch_id}/{file_id}/{safe_original_name}
├── pages/
│   └── {source_page_id}/original.{ext}
├── processed/
│   └── {ocr_run_id}/page.png
├── ocr/
│   └── {ocr_run_id}/raw.json
├── exports/
│   └── {batch_id}/{export_id}/report.pdf
│                         /report.docx
├── backups/
└── logs/
```

### 5.2 文件处理规则

1. 以服务端实际解析的 MIME 类型为准，不能只相信扩展名。
2. 上传时校验文件头、可解码性、大小、数量、SHA-256 和重复文件。
3. 文件先保存到临时目录，完成校验后原子移动到正式目录。
4. 原始文件只读；预处理和 OCR 文件使用新的存储键。
5. 下载接口不直接暴露物理路径，使用授权后的流式响应或短时下载地址。
6. 原图/PDF 预览要检查当前用户是否属于该批次，不能仅凭文件 ID 访问。
7. 导出文件的下载权限与批次权限一致，不能通过猜测 URL 获取。

### 5.3 备份与恢复

- SQLite 数据库和文件存储必须成套备份，不能只备份数据库。
- 备份至少包含数据库文件、原始文件索引、原始文件和导出规则版本。
- 备份过程使用 SQLite 在线备份或短暂只读窗口，不能复制正在写入的半成品文件。
- 恢复后执行外键检查、文件存在性检查、孤儿文件检查和任务状态修复。
- 具体保留天数、备份频率和加密方式为 `[TBD]`，由部署负责人确认。

- 日志默认输出 `request_id`、任务 ID、阶段和错误码，不输出学生姓名、学号和作业原文。

**验证方法：**

### 步骤 3：实现数据库模型、迁移和种子数据

**要做什么：** 创建本章定义的表、外键、索引、检查约束和迁移脚本。  
**为什么做：** 业务对象、版本关系和追溯链必须先稳定，OCR 和评分不能直接写无结构 JSON。  
**具体怎么做：**

1. 开启 SQLite 外键和 WAL 配置。
2. 使用迁移工具创建表，不用运行时静默修改表结构。
3. 创建一个明确标记为演示数据的种子脚本，禁止混入正式测试统计。
4. 写入批次总分、评分点合计、题号唯一、页序唯一等业务校验。
5. 为所有结果表保存输入版本和算法/模型版本。

**验证方法：**

```powershell
python .\backend\scripts\init_db.py
python .\backend\scripts\verify_schema.py
```

**成功标志：** 外键检查通过；重复学号、重复题号、评分点分值不一致、重复页序均能被阻止。

### 步骤 4：实现登录、会话和访问保护

**要做什么：** 实现服务端登录、退出、会话恢复、过期、失败限制和批次访问隔离。  
**为什么做：** 原型登录仅用于交互测试，正式系统不能依赖浏览器本地标志。  
**具体怎么做：**

- 使用密码哈希验证，禁止保存明文密码。
- 建议使用 HttpOnly、Secure、SameSite Cookie 保存会话；不把正式 Token 放在 `localStorage`。
- 登录失败保留账号输入，密码错误次数达到阈值后临时锁定。
- 所有内部接口依赖当前用户；即使知道 ID 也不能访问其他用户数据。
- 退出时撤销会话；页面刷新通过 `/auth/session` 恢复状态。

**成功标志：** 未登录访问内部接口返回 `401`；登录后可访问本人数据；过期会话不能继续调用业务接口。

### 步骤 5：实现班级、学生、批次和评分标准

**要做什么：** 完成批改前配置闭环。  
**为什么做：** 没有班级、学生、题目、参考答案和评分标准，后续 OCR 结果无法归属和评分。  
**具体怎么做：**

1. 实现班级创建、编辑、停用和学生名单维护。
2. 支持手动维护学生；名单文件导入作为 P1 扩展，字段格式需确认。
3. 实现批次草稿保存、编辑、保存并进入上传。
4. 校验批次总分、题目总分、题号唯一和客观题参考答案。
5. 主观题必须绑定同学科且评分点合计一致的评分标准，否则批次只能保存草稿，不能开始批改。
6. 评分标准编辑生成新版本，历史批次保留原版本。

**成功标志：** 配置错误能在字段和接口两端被阻止；已上传批次编辑不会创建重复批次；标准版本变更只使受影响题目失效。

### 步骤 6：实现批量上传、文件校验和页面生成

**要做什么：** 实现批次绑定、逐文件状态、失败重试和图片/PDF 页面记录。  
**为什么做：** 文件是所有后续处理的输入，错误文件不能污染批次，也不能因刷新丢失状态。  
**具体怎么做：**

- 上传前必须带 `batch_id`。
- 服务端重新检查 MIME、扩展名、文件头、大小、数量、内容指纹和解码能力。
- 每个文件独立生成状态；失败项可单独重试。
- PDF 读取真实页数并生成 `source_pages`；自动拆页实现方式 `[TBD]`，但接口要以页面对象为单位。
- 使用 `Idempotency-Key` 防止网络重试造成重复文件。
- 成功上传后批次进入 `pending_ocr`，不能直接跳过 OCR 校对进入评分。

**成功标志：** 文件损坏只影响当前文件；刷新后能查到任务状态；文件名和内容重复有明确提示；原始文件可回读。

### 步骤 7：实现学生多页作业归属

**要做什么：** 为页面生成自动归属建议，并提供教师确认、调整、拆分、合并和失败兜底。  
**为什么做：** 学生归属和页序错误会把答案分配给错误学生，是高风险数据错配。  
**具体怎么做：**

1. 根据文件名、页眉/学号、连续页码等依据生成建议。
2. 把建议写入 `page_groupings`，状态使用 `suggested`，不能静默确认。
3. 检测学生标识冲突、重复页序、页序不连续、多个候选对象和跨页答案冲突。
4. 冲突写入 `anomalies`，页面进入 `needs_review`。
5. 教师确认后写入 `confirmed_by`、`confirmed_at` 和历史记录。
6. 未确认前阻止 `pending_grading` 和正式报告统计。

**成功标志：** 每页都能查到原文件、原页码、合并页序、归属置信度和归属原因；归属失败时原文件和单页记录仍保留。

### 步骤 8：实现图像预处理和 OCR

**要做什么：** 对页面执行方向校正、去噪、版面处理并调用 PaddleOCR。  
**为什么做：** OCR 需要可复现的处理版本和原图证据，便于 bad case 分析和重试。  
**具体怎么做：**

- 读取原始页面，生成新的预处理文件，不修改原始文件。
- 保存处理参数、软件版本、OCR 模型版本和运行耗时。
- 保存文本块、坐标、页码、置信度和原始 OCR JSON。
- 低置信度、无法解码、版面失败进入异常，不把失败写成空题。
- OCR 完成后进入 `pending_correction`，等待教师校对。

**成功标志：** 页面可以从原图定位到文本块；OCR 失败有原因和重试入口；原始 OCR 和校对版本可分别查询。

### 步骤 9：实现 OCR 校对和结构化答案

**要做什么：** 提供教师编辑学生、页序、题目覆盖、答案和确认空题的接口。  
**为什么做：** OCR 结果只是建议，只有经过人工校对的结构化答案才能进入评分。  
**具体怎么做：**

1. 校对保存创建新的 `answer_versions`。
2. 只有勾选“本页包含题目”才保存该题答案。
3. 有文字时禁止同时确认空题。
4. 页序必须为正整数，同一学生不能重复。
5. 按学生作业内页序拼接跨页答案。
6. 修改答案、归属或页序时，使对应题目结果变为 `stale`。
7. 校对确认前执行归属、页序、跨页冲突和题目覆盖完整性校验。

**成功标志：** 教师可以从原图、OCR 文本和答案互相定位；校对失败不丢失原内容；未确认页面不能触发批改。

### 步骤 10：实现题型分派和客观题判分

**要做什么：** 按题目配置把题目分派到规则引擎或主观题流程，并实现客观题规则判分。  
**为什么做：** 不同题型的输入、评分依据和异常处理不同，必须保留分派依据。  
**具体怎么做：**

- 每道题读取 `question_type`、参考答案和规则版本。
- 先做答案规范化，再执行明确的匹配和容错规则。
- 记录规范化前后答案、匹配结果、规则版本、得分和判分理由。
- 默认不使用未经确认的模糊匹配；不同题型的容错规则单独配置。
- 结果越界、答案缺失、规则缺失进入异常。
- 规则结果仍标记为待教师确认，不能直接进入正式成绩。

**成功标志：** 每个客观题结果都能回溯到参考答案和规则版本；越界分数被阻止；规则错误与输入错误可区分。

### 步骤 11：实现主观题结构化 AI 初评

**要做什么：** 使用 DeepSeek 兼容接口生成评分点分数、证据、扣分原因、评语和复核标识。  
**为什么做：** 主观题需要比总分更细的评分依据，教师必须能够核查和调整。  
**具体怎么做：**

1. 调用前脱敏姓名、学号等敏感标识，保存恢复映射在受保护位置。
2. 发送题目要求、校对文本、评分标准版本、评分点和示例作答。
3. 要求模型返回固定 JSON 结构，不接受无法解析的自由文本作为正式结果。
4. 校验评分点是否齐全、单项是否越界、合计是否等于题目总分。
5. 记录模型名、提示词版本、评分标准版本、输入哈希和响应摘要。
6. 超时、限流、空响应、格式错误和重试上限进入异常队列。
7. AI 结果统一显示“AI 生成，教师复核后生效”。

**建议输出结构：**

```json
{
  "score": 11,
  "points": [
    {
      "point_id": "rp_001",
      "score": 5,
      "max_score": 6,
      "evidence": "学生答案中的相关证据",
      "deduction_reason": "与评分点要求的差异"
    }
  ],
  "comment": "鼓励性、建设性的评语",
  "review_required": true
}
```

**成功标志：** 模型输出不能绕过分值校验；失败可有限重试；多次失败自动转人工；AI 初评不进入正式成绩。

### 步骤 12：实现异常队列、任务重试和部分重跑

**要做什么：** 把低置信度、缺页、疑似空题、未匹配、异常分数、模型失败等统一进入异常处理。  
**为什么做：** 单页或单题失败不能导致整批数据丢失，教师需要知道下一步处理动作。  
**具体怎么做：**

- 每个异常使用类型、严重程度、证据、状态和处理结论。
- 上传、OCR、评分和导出任务均使用持久化任务记录。
- 任务领取使用数据库锁定和心跳；超时任务可重新入队。
- 重试次数有限，重试时复用同一输入快照，避免重复写结果。
- OCR 校对或评分标准改变时，计算受影响题目集合，只重跑相关题目。
- 已复核题目重跑前必须二次确认并填写原因。

**成功标志：** 页面刷新、Worker 重启后任务状态可恢复；失败项可以单独重试；成功项不受失败项影响。

### 步骤 13：实现教师复核和正式成绩

**要做什么：** 提供队列、证据、分数、评语、修改原因、确认和历史记录。  
**为什么做：** 教师复核是正式成绩生效的控制点。  
**具体怎么做：**

1. 按异常、低置信度和未复核优先展示队列。
2. 详情按“学生作答 → OCR → 参考答案/评分标准 → AI 建议 → 教师结论”展示。
3. 保存待复核不进入正式成绩。
4. 确认本题写入教师分数、评语、复核人、复核时间和原因。
5. 确认后自动定位下一条未复核题。
6. 汇总时检查当前学生整份作业所有题目是否已复核、是否存在失效结果。

**成功标志：** 教师可以修改 AI 结果；历史能显示前后值和原因；未完整复核学生不会伪装成完整正式成绩。

### 步骤 14：实现报告统计和 PDF/Word 导出

**要做什么：** 生成正式报告和 AI 初评参考报告，并提供 PDF 或 Word 文件任务。  
**为什么做：** 报告是批改闭环的输出，但不同统计口径必须严格分开。  
**具体怎么做：**

- `reviewed` 模式只统计当前批次中整份作业全部题目已复核且未失效的学生。
- `ai_preview` 模式单独展示，可包含未复核结果，但必须显著标注非正式成绩。
- 报告生成前计算输入快照哈希，避免数据变化后下载旧文件。
- 生成任务采用异步接口，前端查询任务状态。
- PDF 建议使用 HTML/CSS 模板渲染为 PDF；Word 建议使用 `.docx` 模板生成。具体库和字体方案 `[TBD]`。
- 导出失败保留失败原因和重试入口，不生成空文件或伪成功记录。

**成功标志：** 报告统计与页面口径一致；导出文件可下载、可打开、状态准确；AI 初评文件不会被误认为正式成绩。

## 7. API 接口设计

### 7.1 API 基础约定

- 基础路径：`/api/v1`。
- 数据格式：JSON；文件上传使用 `multipart/form-data`。
- 认证：服务端会话 Cookie `[SHOULD]`。
- 字符编码：UTF-8。
- 时间：ISO 8601。
- ID：服务端生成不可预测的字符串 ID。
- 所有写操作返回 `request_id`，便于日志追踪。
- 需要防止重复提交的写操作支持 `Idempotency-Key`。
- 需要保护旧页面覆盖新数据的更新接口接收 `version` 或 `If-Match`。

### 7.2 成功响应格式

单对象：

```json
{
  "data": {
    "id": "batch_01J...",
    "status": "draft"
  },
  "meta": {
    "request_id": "req_01J..."
  }
}
```

列表：

```json
{
  "data": [],
  "meta": {
    "request_id": "req_01J...",
    "page": 1,
    "page_size": 20,
    "total": 0
  }
}
```

### 7.3 错误响应格式

```json
{
  "error": {
    "code": "BATCH_CONFIG_INVALID",
    "message": "批次配置不完整，暂不能开始批改",
    "details": [
      {
        "field": "questions[0].rubric_version_id",
        "reason": "主观题缺少同学科评分标准"
      }
    ],
    "request_id": "req_01J..."
  }
}
```

通用状态码：

| HTTP | 错误码示例 | 使用场景 |
|---:|---|---|
| 400 | `INVALID_REQUEST` | JSON、参数或格式错误 |
| 401 | `AUTH_REQUIRED` | 未登录或会话过期 |
| 403 | `FORBIDDEN` | 无权访问对象 |
| 404 | `NOT_FOUND` | 对象不存在或不可见 |
| 409 | `RESOURCE_VERSION_CONFLICT` | 多标签页或旧版本覆盖 |
| 413 | `FILE_TOO_LARGE` | 文件超限 |
| 415 | `UNSUPPORTED_FILE_TYPE` | 文件格式不支持 |
| 422 | `BUSINESS_RULE_VIOLATION` | 分值、题号、页序等业务规则失败 |
| 429 | `RATE_LIMITED` | 本地任务或模型接口限流 |
| 500 | `INTERNAL_ERROR` | 未预期服务器错误 |
| 503 | `DEPENDENCY_UNAVAILABLE` | OCR、模型或存储依赖不可用 |

错误消息使用“原因 + 影响 + 下一步”，不能只返回 `Invalid input` 或 `Something went wrong`。

### 7.15 接口幂等、并发和任务轮询

写操作规则：

1. 文件上传、创建批改运行、创建导出任务必须支持 `Idempotency-Key`。
2. 相同用户、相同幂等键和相同请求体返回同一业务结果。
3. 相同幂等键但请求体不同返回 `409 IDEMPOTENCY_KEY_REUSED`。
4. 页面更新携带 `version`；版本过期返回 `409`，前端需提示刷新或复制未保存内容。
5. 长任务接口立即返回 `202`，不能让浏览器连接等待整批处理完成。
6. 前端首次 1 秒后轮询，之后按 2–5 秒退避；任务完成、失败或需要用户操作时停止轮询。
7. 可选使用 SSE 优化进度推送，但不能把 SSE 作为任务持久化的替代。

## 8. LangGraph、任务队列和评分流程

### 8.1 OCR 流程节点

```text
load_file
  → validate_file
  → split_pages
  → preprocess_page
  → suggest_grouping
  → run_paddleocr
  → persist_raw_ocr
  → detect_ocr_anomaly
  → persist_page_state
  → wait_for_teacher_correction
```

`wait_for_teacher_correction` 是人为控制点。流程不能自动把低置信度 OCR 当成空答案，也不能在未确认学生归属时进入评分。

### 8.2 批改流程节点

```text
load_batch_config
  → validate_batch_config
  → load_confirmed_answers
  → dispatch_question_type
       ├─ objective_rule_score
       └─ subjective_llm_score
  → validate_score_schema
  → detect_anomalies
  → persist_suggested_result
  → aggregate_student_status
  → enqueue_teacher_review
```

### 8.3 Worker 设计建议

首版单实例建议采用“数据库任务表 + 独立 Worker 进程”的方案：

- FastAPI 只负责创建任务和查询任务；
- Worker 以事务方式领取 `queued` 任务；
- 领取时写入 `locked_by`、`started_at`、`heartbeat_at`；
- Worker 崩溃后由恢复扫描把超时锁定任务重新入队；
- 同一实例最多同时处理 4 个学生作业对象，超出进入队列；
- 队列长度建议从 20 开始，最终以性能测试校准；
- 如果后续需要多实例或更高并发，再评估 Redis/Celery 等外部队列。

该方案是实现建议，不是 PRD 已确定的唯一队列技术。必须在性能测试后确认 SQLite 写入锁、OCR 内存占用和 DeepSeek 请求并发。

### 8.4 任务恢复规则

| 情况 | 处理 |
|---|---|
| Worker 心跳超时 | 标记任务可恢复，增加恢复次数，重新入队 |
| 单页 OCR 失败 | 只标记该页失败，其余页面继续 |
| 单题评分失败 | 只标记该题失败，其他题目保留结果 |
| 模型超时 | 按退避策略有限重试，超过上限进入人工复核 |
| 输出 JSON 格式错误 | 不保存为成绩，重试后仍失败则人工处理 |
| 页面刷新 | 前端重新查询任务，不重新创建任务 |
| 数据输入被修改 | 原任务结果标记失效，创建带新输入哈希的新任务 |

### 8.5 结果失效和影响范围

结果输入指纹至少由以下内容计算：

```text
题目配置版本
当前答案版本
评分标准版本
规则版本
模型版本
提示词版本
```

以下修改只使受影响题目失效：

- 单题 OCR 文本或学生答案修改；
- 单页学生归属或页序调整；
- 单题参考答案或容错规则修改；
- 某一主观题评分标准版本修改；
- 模型或提示词升级导致重新评估。

## 9. PDF / Word 报告导出设计

### 9.1 导出范围

首版报告页面已经包含个人成绩和班级统计，因此导出设计预留两类范围：

- `scope=batch`：批次班级报告，包含统计和个人成绩列表；
- `scope=student`：单个学生成绩单，包含逐题结果和复核状态。

如果负责人最终只要求一种范围，另一种接口可以保留但不在首版 UI 暴露。

### 9.2 导出内容基线

#### 批次报告

- 批次名称、班级、学科、满分；
- 报告口径：教师已复核或 AI 初评参考；
- 生成时间和数据统计范围；
- 可统计学生数、平均分、最高分和分数分布；
- 高频错误、题目失分和已有真实数据支持的薄弱项；
- 学生列表：姓名/编号、客观题、主观题、总分、状态；
- 未复核、缺页、结果失效学生的状态说明；
- 报告版本、生成任务 ID 或数据快照标识。

#### 个人成绩单

- 学生标识、批次、班级、学科和满分；
- 每道题的题型、学生答案、得分、满分和复核状态；
- 主观题评分点、证据、扣分原因和教师评语；
- AI 初评与教师最终分的区分；
- 复核时间和结果追溯信息。

具体字段、是否显示完整学生姓名、文件名规则和排版 `[TBD]`。

### 9.3 PDF 生成建议

建议方案：使用后端 HTML/CSS 报告模板渲染为 PDF。

要求：

- 使用固定报告模板，不直接拼接未经转义的 HTML；
- 统一 A4 页面、页眉、页脚、页码和生成时间；
- 中文字体必须在目标部署环境中验证；
- 表格跨页时重复表头；
- 图表同时提供文本摘要或数据表；
- AI 初评文件加醒目标识；
- 无数据显示明确空状态，不生成空坐标轴；
- 导出文件生成后用 PDF 解析和页面渲染检查。

### 9.4 Word 生成建议

建议输出 `.docx`，使用模板或结构化文档生成器。

要求：

- 标题、章节、表格和说明使用可编辑的 Word 结构；
- 不把整份报告仅作为一张图片嵌入；
- 保留 AI 初评与正式成绩的文字标识；
- 表格列宽、长评语换行和中文字体在目标办公软件中验证；
- 导出文件打开失败时任务标记为失败，不显示成功。

### 9.5 导出状态

```text
待生成 → 生成中 → 可下载
                  ├→ 部分失败 → 查看失败项/重试
                  └→ 失败 → 查看原因/重试
```

下载前再次检查：

1. 导出任务属于当前教师；
2. 批次未被归档或删除；
3. 报告数据快照仍然有效；
4. 文件存在且大小大于 0；
5. 文件扩展名和 `format` 一致。

| 设置 | `/settings` | 教师、模型、存储和隐私配置 |

### 10.2 前端实现顺序

#### 阶段 A：应用壳和认证

- 实现 `AuthGuard`、侧边栏、顶部栏、面包屑和页面主区域。
- 接入 `/auth/session`，刷新后恢复登录状态和目标路由。
- 登录失败使用表单错误和 `role=alert`，不使用仅 Toast。
- 移动端侧边栏使用抽屉、遮罩、焦点进入和焦点恢复。

#### 阶段 B：批次配置

- 实现班级/学生弹窗和批次编辑表单。
- 使用统一表单校验：必填、重复题号、分值合计、评分标准绑定。
- 支持“仅保存草稿”和“保存并进入上传”。
- 退出未保存表单时二次确认。

#### 阶段 C：上传和任务状态

- 上传前强制选择批次。
- 每个文件显示校验、保存、成功、失败和重试状态。
- 任务进度不能依赖页面内存；刷新后重新请求 `/tasks/{task_id}`。
- 上传按钮在请求过程中禁用，避免重复提交。

#### 阶段 D：OCR 校对

- 原图/PDF 只读预览和文件页面列表。
- 学生归属、页序、题目覆盖、答案和确认空题编辑。
- 低置信度文本块和异常使用文字、图标和颜色共同表达。
- 桌面端原图与编辑区并排；移动端使用“原图 / 答案与归属 / 题目列表”分段。

#### 阶段 E：智能批改和教师复核

- 左侧复核队列异常优先，右侧详情按证据链展示。
- 客观题显示参考答案、规则版本和判分理由。
- 主观题显示评分点、证据、扣分原因、评语、模型和提示词版本。
- “保存待复核”和“确认本题并查看下一题”分开。
- 不提供不加确认的“接受全部 AI 结果”按钮。

#### 阶段 F：报告和导出

- 报告页提供 `reviewed` / `ai_preview` 口径切换。
- 正式成绩和 AI 初评使用不同状态说明。
- 报告统计提供图表、文本摘要和表格替代。
- 导出提供 PDF 或 Word 选项；未满足条件时显示原因和恢复方式。

### 10.3 页面与接口依赖

| 页面 | 首屏接口 | 写入接口 | 长任务 |
|---|---|---|---|
| 登录 | `/auth/session` | `/auth/login`、`/auth/logout` | 否 |
| 工作台 | `/workbench/summary`、`/workbench/tasks` | 无 | 任务轮询 |
| 作业管理 | `/classes`、`/batches` | 班级、学生、批次接口 | 否 |
| 上传 | `/batches/{id}`、`/files` | 上传、重试 | 上传任务 |
| OCR | `/pages`、`/pages/{id}` | 归属、校对、确认 | OCR 任务 |
| 批改 | `/review-queue`、`/grading-results` | 发起、重跑、复核 | 批改任务 |
| 评分标准 | `/rubrics`、`/versions` | 创建、编辑、启停 | 否 |
| 报告 | `/reports`、`/statistics` | 创建导出 | 导出任务 |
| 设置 | `/settings` | 配置、清理 | 连接测试/清理 |

### 10.4 前端数据和缓存规则

- 服务器数据使用统一请求层管理；不要让页面组件自行拼接接口 URL。
- 批次上下文保存在路由查询参数和必要的页面状态中，刷新后可恢复。
- 未保存表单使用本地内存暂存，但不能把本地存储作为正式数据唯一备份。
- 文件预览对象 URL 在页面离开或文件切换时释放。
- 列表超过 50 条时使用分页或虚拟化。
- 搜索、窗口调整和滚动事件使用 debounce/throttle。
- API 错误转为“原因 + 影响 + 下一步”，字段错误定位到具体控件。

### 10.5 UI/UX 实现约束

- 使用设计文档定义的颜色、字号、间距、圆角和阴影 token。
- 正文与背景至少满足 4.5:1 对比度，焦点和非文本控件满足对比度要求。
- 状态不能只依赖颜色；状态标签必须包含文字。
- 主要触控目标不小于 44×44px。
- 支持键盘访问、`aria-label`、`aria-invalid`、`aria-describedby`、`aria-expanded` 和焦点恢复。
- 图表提供文本摘要或表格替代。
- 验收宽度：375px、768px、1024px、1440px。

## 11. 安全、隐私和合规

### 11.1 认证与权限

- 内部页面和接口都必须经过服务端认证。
- 首版单教师模式不等于不需要权限校验；至少校验用户是否拥有目标班级、批次、文件和报告。
- 会话必须支持过期、退出和失败限制。
- 密码只保存安全哈希，API Key 不出现在前端、日志和普通 API 响应中。

### 11.2 外部模型调用

- API Key 只由后端读取。
- 调用 DeepSeek 前对姓名、学号等标识脱敏。
- 保存脱敏映射的受保护位置、访问权限和清理策略 `[TBD]`。
- UI 显示外部模型可能影响隐私、费用、延迟和服务可用性。
- 模型返回只作为初评建议，必须经过结构校验和教师复核。
- 模型超时、限流、空响应和格式错误不能写入正式成绩。

### 11.3 文件安全

- 文件类型使用内容检测，不只看扩展名。
- 图片/PDF 预览使用服务端授权接口。
- 文件名进行安全处理，不能用于目录穿越。
- 下载链接短时有效或每次验证会话。
- 对恶意或损坏 PDF、超大图片和异常压缩文件设置资源限制。

### 11.4 日志和审计

日志可以记录：

- `request_id`、用户 ID 的不可逆摘要、任务 ID、批次 ID、阶段、耗时、错误码；
- OCR/模型/规则版本；
- 重试次数和处理结果。

日志不能记录：

- API Key；
- 完整学生姓名、学号；
- 完整作业原文和模型提示词中的敏感内容；
- 可直接下载原始文件的路径。

审计记录必须覆盖：批次创建、文件重试、归属确认、OCR 校对、批改启动、结果失效、教师改分、教师确认、导出和数据清理。

### 12.3 OCR 评测

评测前必须建立版本化 manifest，包含：

- 学科、题型、页数和样本来源；
- 样本授权、脱敏和使用限制；
- 印刷体、工整手写体、横竖版、分栏、多页和混排标签；
- 训练/验证/测试按 8:1:1 或负责人确认的比例划分；
- 字符级、文本块级和页面级计算方式；
- 低置信度和失败样本是否计入分母。

报告至少给出准确率、编辑距离、失败率、人工接管比例和 bad case。

### 12.4 评分评测

客观题：逐题统计正确、错判、漏判、格式异常和规则误配。  
主观题：由至少两名人工评分者按统一档位评分，预先定义冲突仲裁和一致率算法。不能用平均分差代替档位一致率。

### 12.5 性能评测

在 PRD 首版目标硬件上运行 1、2、4、8 个学生作业对象：

- 记录上传、页面读取、预处理、OCR、规则评分、模型调用、队列等待和导出耗时；
- 报告平均值、P50、P95、最大值、失败重试和人工接管；
- 记录 CPU、内存、磁盘、GPU（如使用）和 DeepSeek 请求并发；
- 只有 1、2、4 并发均无数据丢失、死锁和状态错乱时，才可确认 4 并发目标；
- 8 并发用于观察降级，不承诺达到 60 秒目标。

### 12.6 UI/UX 验收

- 375px 无页面级横向溢出；
- 768px 平板布局可用；
- 1024px 窄桌面/横屏可用；
- 1440px 内容不无限拉伸；
- OCR 和复核移动端为分段或单列；
- 键盘可完成登录、表单、弹窗、校对和复核；
- 错误可被读屏识别，图表有表格/文本替代；
- 删除、重跑、放弃编辑和修改已复核结果都有确认；
- AI 初评和正式成绩状态明显区分；
- PDF/Word 导出失败不会显示虚假成功。

### 13.2 配置项

```text
APP_ENV=development
APP_SECRET_KEY=<server-only-secret>
DATABASE_URL=sqlite:///E:/data/pixiaozhi/app.db
STORAGE_ROOT=E:/data/pixiaozhi

OCR_MODEL_VERSION=<待确认>
REPORT_EXPORT_FORMATS=pdf,docx
```

密钥不能提交到 Git、前端构建产物、日志或数据库备份明文中。

### 13.3 启动顺序

```powershell
# 1. 激活已确认的 Python 环境
python --version

# 2. 初始化或迁移数据库
python .\backend\scripts\init_db.py

# 3. 启动 FastAPI
uvicorn app.main:app --host 127.0.0.1 --port 8000

# 4. 单独启动后台 Worker
python -m app.workers.runner

# 5. 启动前端开发服务
npm run dev
```

正式部署时应使用服务管理器托管 API 和 Worker，不能依赖开发服务器窗口长期运行。

### 13.4 健康检查

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/health/live" -Method Get
Invoke-RestMethod -Uri "http://127.0.0.1:8000/health/ready" -Method Get
```

成功标志：

- `live` 表示进程存活；
- `ready` 表示数据库连接、迁移状态和存储目录可用；
- 模型 API 未配置时，`ready` 不应伪装成“模型已连接”，可以返回“核心服务可用、模型未配置”的分项状态。

### 13.5 故障处理

| 故障 | 检查 | 处理 |
|---|---|---|
| 前端请求 401 | 会话过期、Cookie、服务端时间 | 重新登录，不清除未保存草稿前先提示 |
| 文件保存失败 | 存储空间、权限、文件锁 | 保留失败项，释放空间后单独重试 |
| OCR Worker 停止 | Worker 心跳和任务锁 | 重启 Worker，恢复超时任务 |
| SQLite 锁定 | 长事务、并发写入、WAL | 缩短事务，检查 Worker 并发，必要时升级数据库方案 |
| DeepSeek 超时 | 网络、限流、请求体大小 | 有限重试，超过上限转人工 |
| 导出文件打不开 | 模板、字体、生成依赖 | 标记导出失败，保留错误日志和重试入口 |
| 数据库恢复后文件缺失 | 备份是否成套 | 使用同一时间点的数据库和文件备份恢复 |

## 18. 结论

批小智首版应围绕“批次上下文、原图证据、OCR 校对、评分依据、AI 建议、教师确认、正式报告”实现可追溯闭环。

技术实现的核心控制点是：

1. 原始文件和原始 OCR 只读保存，所有教师修改产生新版本。
2. 学生归属、页序和答案未确认时不能进入评分和正式统计。
3. 客观题和主观题结果都必须保存评分依据、规则/模型版本和处理状态。
4. AI 结果只能作为建议，教师确认后才进入正式成绩。
5. 所有长任务采用持久化任务 ID、状态查询、有限重试、恢复和部分重跑。
6. 报告导出格式确定为 PDF 或 Word，但导出字段、排版、文件名、是否同时支持两种格式和最终生成库仍需确认。

本文档完成后，研发团队应先完成第 16 章待确认事项，再按第 14 章顺序进行数据库、后端、前端、联调和验收，避免在未确认模型、数据授权、部署和导出规则前直接承诺最终效果。
