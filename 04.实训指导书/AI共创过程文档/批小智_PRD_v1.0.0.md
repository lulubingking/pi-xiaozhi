## 2. 产品背景与定位

### 2.1 项目背景（任务书明确）

教师需要频繁处理纸质或电子作业，主观题批改耗时较长，人工评分还可能出现尺度不一致。任务书希望通过“作业上传—OCR 识别—题型分派—智能评分—结果汇总”的流水线，降低重复批改工作量，同时保留教师校对和复核。

现有市场已经出现作文批改、学校阅卷和教师 AI 评分产品。因此，“面向个人教师的轻量 AI 批改工具仍属空白”不能作为已经验证的市场事实。批小智需要在目标用户、作业输入方式、评分依据可追溯性和教师复核效率上形成具体定位。

### 2.2 产品定位

> 面向国内个人教师的作业批改与复核工作台：以可复用的评分标准为依据，帮助教师完成整批作业的识别校对、逐题评分、异常处理和成绩报告输出。

### 2.3 核心价值

| 价值方向 | 产品体现 |
|---|---|
| 批改效率 | 批量上传、异步处理、客观题自动判分、主观题 AI 初评，减少重复操作 |
| 结果可控 | 原图、OCR 文本、评分依据和 AI 结果可以对照，教师可以修改识别、分数和评语 |
| 评分一致 | 评分点、分值和示例作答形成可复用的评分标准，减少同一批次内尺度漂移 |
| 班级洞察 | 汇总个人与班级成绩、错误分布和知识点薄弱项，支持后续讲评 |
| 数据合规 | 调用模型前脱敏，AI 结果显著标识，正式成绩以教师复核为准 |

### 2.4 竞品结论

| 结论类型 | 结论 |
|---|---|
| 事实 | 题小小、河马智能批改等产品公开支持手写作文、班级批量处理和报告；批改网覆盖英语写作自动批改；CoGrader 支持自定义评分标准、AI 初评和教师审核；Gradescope 支持答案分组和评分量表 |
| 推理 | 拍照上传、AI 评分、评语生成、批量处理和报告已经是行业基础能力，批小智应把“教师复核效率”和“评分依据可核查”作为重点体验 |
| 待验证 | 本项目与竞品在相同作业集上的 OCR 准确率、评分一致率、批改耗时和教师操作成本尚未完成对照测试 |

## 3. 产品目标与范围

### 3.1 总体目标（任务书明确）

开发一款可在主流浏览器运行的 AI 自动批改作业 Web 应用。教师上传作业图片或 PDF，选择语文、数学或英语及对应常规题型，录入参考答案与评分要求，系统完成 OCR、题型分派、客观题判分、主观题评分、评语生成、异常标注和教师复核。报告查看属于首版闭环，批改结果支持导出为 PDF 或 Word；具体导出字段、文件名规则和实现细节在最终交付阶段补充。

### 3.2 量化目标

以下是任务书提出的**目标值，不是已验证结果**。

| 指标 | 任务书目标 | 验收前需要补充的口径 |
|---|---:|---|
| 印刷体 OCR 字符识别准确率 | ≥95% | 样本规模、字符级计算方法、字体和拍摄条件、模型版本与硬件 |
| 工整手写体 OCR 字符识别准确率 | ≥85% | “工整”定义、语言/学科、标注方法和失败样本处理 |
| 客观题判分准确率 | ≥99% | 题型范围、答案格式、容错规则和统计分母 |
| 主观题评分与人工评分档位一致率 | ≥85% | 评分档位定义、人工评分人数、冲突仲裁和一致率算法 |
| 单份作业端到端批改时间 | ≤60 秒 | 页数、题量、模型 API、并发数、平均/P95/最大耗时和重试是否计入 |
| 单实例批改并发（产品建议） | 4 个学生作业对象同时处理 | 在单教师模式下，前台交互保持 1 个会话；其余任务进入队列；按实际部署硬件和代表性作业集验证 |

### 3.3 产品范围

| 范围层级 | 内容 |
|---|---|
| 任务书全量范围 | 作业管理、OCR、智能批改、评分标准知识库、报告、前后端分离 WebApp、评测与配套文档交付 |
| 已确认首版范围 | 语文、数学、英语三类学科；覆盖常规题型；支持多样作业版式识别；实现图片/PDF 批量上传、OCR 校对、客观题与主观题评分、教师复核和报告查看 |
| 最终交付阶段补充 | 完成 PDF 或 Word 导出实现，并确定导出字段、文件名规则、排版和失败重试验收 |
| 后续扩展 | 学校级权限与 LMS 集成、学生端自主订正，以及超出首版常规题型的复杂开放题评分 |
| 不自动承诺 | 不承诺完全替代教师；不承诺所有手写体和所有学科都达到量化目标；不把 AI 输出直接作为正式成绩 |

## 4. 目标用户与使用场景

### 4.1 目标用户

| 用户 | 目标 | 主要任务 |
|---|---|---|
| 个人教师（核心） | 高效完成日常作业批改并保留控制权 | 创建班级/批次、上传、校对、复核、查看报告 |
| 教研或备课组教师（次要） | 复用评分标准并比较班级表现 | 维护评分标准、查看统计、参与复核 |
| 单教师配置（P1） | 维护本人运行配置 | DeepSeek 接口、文件保存和数据清理配置；不包含多教师协作 |

### 4.2 登录与访问控制

- 教师进入工作台前必须完成账号密码登录。
- 未登录用户不得访问工作台、作业管理、OCR 校对、智能批改、评分标准、批改报告和设置页面。
- 登录失败时保留表单内容，并显示明确错误提示。
- 支持退出登录；支持由教师主动选择是否在本机保持登录。
- 刷新页面后恢复有效会话；未登录访问内部页面地址时跳转到登录页。
- 首版仍为单教师模式，不包含多教师协作、学校级权限和细粒度角色权限。
- HTML 原型中的登录仅用于交互测试，不代表真实身份认证。正式产品必须实现服务端认证、密码安全存储、会话过期、登录失败限制和权限校验。

### 4.3 典型使用场景

1. 教师创建“八年级英语单元测试”批次，上传整批 JPG/PDF，并录入参考答案和评分标准。
2. 系统完成图像预处理与 OCR，教师在原图和识别文本之间逐题校对，修正姓名、题号和答案。
3. 客观题按规则判分；主观题按评分点生成分项分数、证据、扣分原因和评语。
4. 系统把低置信度、疑似空题、缺页、题目未匹配和异常分数放入复核队列。
5. 教师批量确认正常结果，逐份处理异常，修改 AI 分数或评语后查看班级报告；批改结果可导出为 PDF 或 Word，具体实现规则在最终交付阶段补充。

## 5. 产品架构与导航结构

### 5.1 一级导航

| 一级导航 | 二级功能 | 核心产出 |
|---|---|---|
| 工作台 | 待处理任务、批改进度、异常提醒 | 任务状态与下一步操作 |
| 作业管理 | 班级、作业批次、上传记录、参考答案 | 可批改的作业批次 |
| OCR 校对 | 作业管理上传成功后的批次内处理步骤；原图、文本、题号/学生归属、修正记录 | 可用于评分的结构化答案 |
| 智能批改 | 题型分派、规则判分、主观题评分、评语、异常 | AI 初评结果 |
| 评分标准 | 标准模板、评分点、分值、示例、版本 | 可复用评分标准 |
| 批改报告 | 个人结果、班级统计、错误与薄弱项 | 教师复核后的成绩和报告；支持 PDF 或 Word 导出 |
| 设置（单教师配置） | DeepSeek API、存储、数据保留 | 本地或单账号运行配置 |

### 5.2 模块关系

```text
教师
  └─ Web 应用
      ├─ 工作台
      ├─ 作业管理 ──> 上传成功后进入批次内 OCR 校对 ──> 结构化答案
      ├─ 智能批改 ──> AI 初评与异常
      ├─ 评分标准 ──> 为规则评分和主观题评分提供依据
      └─ 批改报告 ──> 教师复核后的成绩与班级分析

支撑能力：React、FastAPI、LangGraph、PaddleOCR、OpenCV/PIL、Python 规则引擎、LLM API、SQLite、文件存储
```

## 6. 核心业务流程

| 阶段 | 教师操作 | 系统处理 | 可回退点 |
|---|---|---|---|
| 1. 创建批次 | 选择班级、学科、题型，按题号录入参考答案/评分标准 | 生成批次和评分标准版本 | 保存草稿；草稿可重新编辑 |
| 2. 上传采集 | 先选择所属批次，再选择 JPG/PNG/PDF，查看逐文件进度 | 校验格式、大小、文件内容和数量并保存原文件 | 失败文件单独重试；上传完成后进入当前批次 OCR |
| 3. 识别校对 | 查看原图和 OCR 文本，修正学生/题号/文字 | 预处理、版面分析、OCR、置信度计算 | 保留原 OCR；修正形成新版本 |
| 4. AI 批改 | 发起批改或选择部分重跑 | 题型分派、规则评分、LLM 评分与评语、异常标记 | 只重跑受影响题目或结果 |
| 5. 教师复核 | 处理异常、调整分数/评语、确认结果 | 记录复核人、时间、修改前后值和原因 | 复核前可回到校对或重批 |
| 6. 报告查看 | 查看个人与班级统计 | 汇总已复核结果；支持 PDF 或 Word 导出 | 最终交付阶段补充导出实现和字段规则 |

### 6.1 结果控制原则

- OCR 失败不等于空题。
- 相似度提示不等于抄袭结论。
- AI 评分只能标记为“建议/待复核”。
- 教师确认后，结果才进入最终成绩。
- 评分标准或 OCR 文本修改后，只重新计算受影响题目及其汇总。

## 7. 功能需求

### 7.1 作业管理

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| HM-001 | P0 | 教师可以创建班级并维护学生标识 | 支持创建、编辑、停用班级；学生姓名/编号可导入或手动维护；重复标识有提示 |
| HM-002 | P0 | 教师可以创建作业批次，设置学科、题型、总分和批次信息 | 批次可保存草稿；缺少必要字段时不能发起批改 |
| HM-003 | P0 | 支持 JPG、PNG、PDF 批量上传并显示进度 | 逐文件显示成功/失败；格式、大小和数量校验；失败项可重试 |
| HM-004 | P0 | 批次中可以录入参考答案和评分标准版本 | 客观题答案与题号绑定；主观题绑定评分点和分值，或明确为待配置 |
| HM-005 | P0 | 系统按学生将多个多页文件归并为一个学生作业对象，并允许教师修正归属 | 每页保留 `student_id`、`assignment_group_id`、`source_file_id`、`page_index`、`page_sequence`、`grouping_confidence` 和 `grouping_reason`；教师可在确认点调整归属；无法确认时进入待处理队列，不得静默合并 |
| HM-006 | P0 | 支持不同拍摄、扫描和排版形式的作业页面识别 | 对横竖版、不同页边距、题目分栏、手写/印刷混排等样本进行版面分析；无法可靠识别时显示原因并进入人工处理 |

补充交互规则：

- 创建批次支持“仅保存草稿”和“保存并进入上传”；草稿可重新打开并回填修改。
- 上传前必须选择具体所属批次；上传完成后只能进入当前批次的 OCR 校对。
- 每个文件单独显示成功、失败、进度和失败原因；失败项可重新选择文件重试。
- 文件内容与扩展名不一致、文件损坏、超出大小或数量限制时阻止该文件保存，不能影响同批次其他文件。
- 批次编辑不得创建重复记录；已上传批次仍保留原文件、页面和学生关联。

### 7.2 OCR 识别与校对

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| OCR-001 | P0 | 对上传图片/PDF 执行方向校正、去噪和版面预处理 | 记录处理状态和处理版本；原始文件不被覆盖 |
| OCR-002 | P0 | 输出带位置、页码和置信度的文本块 | 每个文本块能定位到原图区域，并可按题号/学生关联 |
| OCR-003 | P0 | 提供原图与识别文本对照校对界面 | 教师可编辑文本、题号和学生归属；保存修改人、时间和版本 |
| OCR-004 | P0 | 识别失败或低置信度结果进入待处理队列 | 失败项显示原因；不得自动写成空答案；可人工录入或重试 |

补充校对规则：OCR 校对必须从具体上传批次进入，并显示批次、班级、学生、原文件和页码；教师可手动选择学生、调整页序、逐题录入学生答案或确认空题。未确认归属、重复页序、页序不连续或跨页答案冲突时，不得进入批改。

### 7.3 智能批改

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| GRD-001 | P0 | 按题型将题目分派给规则引擎或主观题评分流程 | 每道题有题型、评分方式和处理状态；无法分派时进入异常 |
| GRD-002 | P0 | 客观题按参考答案和容错规则判分 | 记录匹配答案、规则版本、得分和判分理由；超范围结果被拦截 |
| GRD-003 | P0 | 主观题依据评分点、分值和示例作答逐项评分 | 输出各评分点分数、证据、扣分原因、评语和复核标识；总分通过范围校验 |
| GRD-004 | P0 | 自动标注低置信度、疑似空题、缺页、题目未匹配和相似作答 | 异常类型、置信度、证据和处理状态可查看；教师可忽略或确认 |
| GRD-005 | P1 | 支持模型超时、限流和可控重试 | 重试次数有限；失败原因可见；多次失败自动转人工 |

### 7.4 评分标准知识库

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| RUB-001 | P0 | 按学科和题型维护评分标准 | 支持创建、编辑、停用和查看；必填字段和分值范围校验 |
| RUB-002 | P0 | 评分标准包含评分点、分值分配和示例作答 | 评分点分值合计与题目总分一致；示例可关联评分点 |
| RUB-003 | P1 | 支持导入和跨任务复用 | 导入失败有字段级提示；批改时绑定具体版本 |
| RUB-004 | P0 | 评分标准变更后只使受影响结果失效 | 系统标记旧结果待重批；未受影响题目不被无故重跑 |

补充规则：评分点分值合计必须等于单题分值；全部题目分值合计必须等于批次总分。停用标准不能用于新批次，但历史批次保留已绑定版本；编辑标准后版本递增，仅使绑定该版本的题目结果失效。

### 7.5 教师复核与批改报告

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| RPT-001 | P0 | 教师可以逐份、逐题查看原图、识别文本、评分和评语 | 各信息可互相定位；异常优先展示 |
| RPT-002 | P0 | 教师可以修改分数、评语和异常处理结论 | 保存修改前后值、原因、人员和时间；可查看历史 |
| RPT-003 | P0 | 输出个人成绩单和班级成绩统计 | 统计口径与已复核结果一致；未复核结果有明显标识 |
| RPT-004 | P1 | 展示得分分布、高频错误和知识点薄弱项 | 图表有明确统计范围和时间；无数据时显示空状态 |
| RPT-005 | P1（最终交付） | 支持批改结果导出为 PDF 或 Word | 格式已确定；最终交付阶段补充导出字段、文件名规则、排版和失败重试验收 |

补充统计规则：正式报告只统计当前批次中、整份作业全部题目已教师复核且未失效的学生。AI 初评可单独查看，但不得混入正式成绩。学生答案或评分依据修改后，相关结果退出正式报告，直到重新初评并复核。

## 8. 核心数据与业务规则

### 8.1 核心数据对象

| 对象 | 关键字段 | 关系/用途 |
|---|---|---|
| 用户/教师 | id、姓名、角色、状态 | 创建并操作班级、批次和复核记录 |
| 班级/学生 | 班级 id、学生 id、姓名/编号 | 将作业和成绩归属到具体对象；敏感标识可脱敏 |
| 作业批次 | 学科、题型、总分、状态、创建人 | 一次批量批改的业务容器 |
| 提交/页面 | 原文件、页码、处理版本、归属 | 保留原始作业与页面层级信息 |
| 题目/答案 | 题号、题型、文本、坐标、置信度 | 连接 OCR 结果与评分流程 |
| 评分标准 | 版本、评分点、分值、示例 | 提供规则评分和 LLM 评分依据 |
| AI 评分结果 | 模型/提示词版本、分项分数、证据、异常 | 待教师复核的初评结果 |
| 复核记录 | 修改前后值、原因、人员、时间 | 形成可追溯的最终成绩依据 |

### 8.3 数据保存与恢复

- 批次、班级、学生、题目、答案、评分和复核记录必须按业务对象持久化。
- 页面刷新后恢复有效登录状态、当前页面、当前批次、当前文件/页面及已保存结果。
- 原始图片/PDF 和原始 OCR 结果只读保存，不被校对结果覆盖。
- 上传或保存中断后，未完成文件标记为失败或待重试，不得显示为成功。
- 存储失败必须明确提示，不能显示虚假的保存成功。
- 多标签页同时修改同一份数据时，应提示冲突并阻止旧页面覆盖新数据。
- HTML 原型可使用 `localStorage` 保存结构化数据、使用 `IndexedDB` 保存原文件；正式产品应使用后端数据库和文件存储。

### 8.4 学生多页作业归属字段与兜底

同一学生的多个多页文件必须先归并为一个“学生作业对象”，再进入 OCR 和批改。归属既要支持自动建议，也要保留人工确认和失败兜底。

| 字段 | 说明 |
|---|---|
| `student_id` | 归属的学生标识；无法识别时为空并进入人工确认 |
| `assignment_group_id` | 同一学生、同一批次下合并后的作业对象标识 |
| `source_file_id` | 原始图片/PDF 文件标识，支持一个作业对象关联多个文件 |
| `page_index` | 原文件内的页序 |
| `page_sequence` | 合并后的作业内页序，可由教师调整 |
| `grouping_confidence` | 自动归属置信度 |
| `grouping_reason` | 归属依据，如文件名、页眉/学号、连续页码或人工指定 |
| `grouping_status` | `suggested`、`confirmed`、`needs_review`、`failed` |
| `confirmed_by` / `confirmed_at` | 人工确认人和确认时间 |

人工确认点：首次自动归并后、检测到学生标识冲突时、页序不连续时、同一学生出现多个候选作业对象时。  
失败兜底：保留原文件和单页记录，标记为 `needs_review`；教师可以手动选择学生、调整页序、拆分或合并；在未确认前不得进入最终评分汇总。

### 8.5 状态流转

作业批次：

```text
草稿 → 上传中 → 待识别 → 识别中 → 待校对 → 待批改 → 批改中 → 待复核 → 已复核
                                  ↘ 部分失败/需处理 → 处理后继续
```

单份作业：

```text
待归属 → 已归属 → OCR 待校对 → 评分待复核 → 异常待处理 → 教师已确认
```

### 8.6 业务规则

1. 原始作业文件和原始 OCR 结果只读保存，教师修正产生新版本。
2. 任何得分必须绑定题目、学生、评分标准版本和评分算法/模型版本。
3. 评分点分值合计、题目总分和批次总分必须经过范围与合计校验。
4. OCR 低置信度、缺页、疑似空题、题目未匹配、异常分数和模型失败默认进入人工复核。
5. 教师复核前的 AI 结果只能标记为“建议/待复核”，导出时必须明确复核状态。
6. 评分标准或 OCR 文本修正后，只重新计算受影响题目及其汇总。
7. 草稿可重新编辑；已上传批次修改后不得创建重复批次，且必须保留原文件、页面和学生关联。
8. 整份作业的全部题目完成教师复核后，才计入正式总分；AI 初评只能作为非正式参考。

## 9. AI 识别与评分要求

### 9.1 OCR 输出

| 输出项 | 要求 |
|---|---|
| 文本 | 保留原始文本、校对文本和版本关系 |
| 位置 | 至少记录页码、文本块坐标和题目/学生关联 |
| 置信度 | 按文本块或答案给出置信度，并用于异常分流 |
| 图像 | 保留原图、预处理图和变换参数，便于复核与复现 |

### 9.2 评分输出

| 评分类型 | 输入 | 输出 |
|---|---|---|
| 客观题 | 题目、学生答案、参考答案、容错规则 | 是否匹配、得分、规则版本、判分理由 |
| 主观题 | 校对文本、题目要求、评分标准、示例作答 | 评分点分数、引用证据、扣分原因、评语、复核标识 |
| 异常检测 | OCR 置信度、答案完整性、相似度信号 | 异常类型、证据、严重程度、处理状态；不直接下结论 |

### 9.3 外部模型调用约束

- **已确认：** 主观题评分和评语生成使用 DeepSeek-V4.1-Flash，并按 OpenAI 兼容接口接入。
- **实现参数：** DeepSeek 官方 API 的模型名使用 `deepseek-flash`；具体接口地址、鉴权配置、价格、限流、服务等级和数据协议待补充。
- 调用前对姓名、学号等敏感信息进行脱敏；需要明确脱敏规则、恢复映射保存位置和外部 API 是否允许处理作业内容。
- 提示词、评分标准版本和模型版本必须可记录，以支持问题定位和结果复现。
- 模型超时、限流、空响应、格式错误和评分越界必须进入可恢复异常流程。

### 9.4 原型实现边界

当前 HTML 原型仅用于验证登录入口、批次配置、草稿编辑、班级与学生关联、文件上传、原图预览、人工 OCR 校对、客观题规则判分、主观题模拟评分、教师复核和报告统计。

HTML 原型尚未实现真实账号认证、真实 OCR、手写识别、自动学生归属、自动 PDF 拆页、真实 DeepSeek 调用、真实主观题语义评分、后端数据库、多教师权限和报告导出。原型中的登录、主观题评分和演示数据不得作为正式产品能力或算法指标验收依据。

## 10. 页面与交互要求

| 页面 | 主要区域 | 关键交互与状态 |
|---|---|---|
| 工作台 | 任务列表、进度、异常数、最近批次 | 按状态进入下一步；显示处理中、部分失败和待复核 |
| 登录 | 账号、密码、会话选项 | 未登录拦截内部页面；登录失败提示；登录成功进入工作台；支持退出 |
| 创建批次 | 班级、学科、题型、总分、答案、评分标准 | 草稿保存；缺字段提示；可预览评分配置 |
| 批量上传 | 拖拽区、文件列表、进度和失败原因 | 分文件重试；禁止不支持格式；显示大小限制 |
| OCR 校对 | 原图、文本或题目列表 | 定位同步、编辑、归属调整、低置信度高亮 |
| 批改复核 | 题目导航、评分依据、AI 结果、教师编辑区 | 异常优先；一键接受/修改；保留历史 |
| 班级报告 | 成绩单、分布、高频错误、薄弱项 | 选择批次范围；区分 AI 初评和教师已复核数据；支持 PDF 或 Word 导出 |

### 10.1 交互状态要求

- 所有长任务显示等待、处理中、成功、部分失败和失败状态。
- 上传、识别和批改过程不得因页面刷新而丢失任务状态。
- 空数据、无权限、网络异常和模型超时必须有可理解的提示和下一步操作；PDF/Word 导出需在最终交付阶段补充相应错误处理。
- 评分结果页面必须显著显示“AI 生成，教师复核后生效”等状态信息。
- 任务书要求适配 PC 和移动端浏览器；首版优先保证桌面端完整流程，移动端需单独做上传、查看和复核验收。

### 10.2 登录与通用交互要求

- 登录页是系统入口；未登录时不得通过页面地址直接访问内部功能。
- 登录失败保留账号内容，并显示可理解的错误信息；登录成功后恢复工作台。
- 支持退出登录和本机保持登录选项；正式产品需要服务端会话、过期和权限校验。
- 必填字段缺失、分值越界、评分点合计不一致、重复学号、重复页序等错误必须在字段附近提示，并提供错误汇总定位。
- 创建批次支持“仅保存草稿”和“保存并进入上传”；草稿可重新打开修改。
- 上传必须先选择批次；逐文件显示进度、成功/失败原因和重试入口；失败文件不得影响其他文件。
- OCR 校对从具体批次上传完成后进入，不设置脱离批次的独立处理路径。
- 离开未保存表单或校对内容时必须二次确认；弹窗支持关闭按钮、Escape 和焦点恢复。
- 移动端不得出现页面级横向溢出；数据表在窄屏下改为卡片或提供可操作的横向滚动区域。
- 所有状态不能只依赖颜色表达；图标按钮需提供可访问名称；支持减少动画偏好。

## 11. 技术架构与技术约束

### 11.1 技术选型

| 技术模块 | 任务书选型 | 职责 | 待确认/说明 |
|---|---|---|---|
| 前端 | React | 上传、批次、校对、复核、报告页面 | 任务书未明确 JavaScript 或 TypeScript；建议采用 TypeScript |
| UI/样式 | Tailwind CSS / Ant Design | 页面样式与组件 | 两者组合方式待确定，避免重复建设 |
| 后端语言 | Python 3.12+ | 业务、图像处理、评分逻辑 | 与前端 React 分工明确 |
| 后端框架 | FastAPI | REST API、任务提交、结果查询 | 异步任务队列实现未指定 |
| 流程编排 | LangGraph | 预处理、OCR、题型分派、评分、汇总 | 节点重试、检查点和可恢复策略需设计 |
| OCR | PaddleOCR | 印刷体/手写识别、位置输出 | 具体模型、运行设备和模型来源待确定 |
| 图像处理 | OpenCV / PIL | 校正、去噪、版面预处理 | 参数需以 bad case 评测调优 |
| 客观评分 | Python 规则引擎 | 参考答案匹配和判分 | 题型和容错规则需先定义 |
| 主观评分 | DeepSeek-V4.1-Flash API（模型名 `deepseek-flash`，OpenAI 兼容接口） | 评分与评语生成 | 接口地址、鉴权、价格、限流和数据协议待确认 |
| 数据库 | SQLite | 用户、班级、批次、文本、结果、统计 | 并发规模和备份策略需验证 |
| 文件存储 | 文件形式持久化 | 原图/PDF、OCR 模型、评分标准配置 | 目录结构、保留期限、加密和清理策略待确定 |

### 11.2 推荐处理链路

```text
React
  → FastAPI
    → 后台任务/任务队列（实现方式待确认）
      → LangGraph 流程
        → OpenCV/PIL + PaddleOCR
        → 题型分派
          ├─ Python 规则引擎：客观题
          └─ DeepSeek API：主观题评分与评语
        → 异常标注与结果汇总
  → SQLite + 文件存储
  → React 复核与报告
```

### 11.3 技术边界

1. SQLite 适合首版单机或低并发场景；目标并发和多用户部署方式确认后再决定是否升级数据库。
2. FastAPI 本身不等于完整任务队列，需要确定后台任务、队列、状态持久化和失败恢复方案。
3. SQLite 保存结构化业务数据，原图/PDF/OCR 模型和评分标准配置保存为文件；两者的备份与删除策略需要一致设计。
4. 大模型 API 的外部依赖会影响准确率、延迟、费用和隐私，必须单独记录和验收。

### 11.4 并发与部署建议

#### 并发定义

本 PRD 将“并发”定义为**同一部署实例同时处理的学生作业对象数量**，而不是在线教师人数或 HTTP 请求数。单教师模式下，前台交互并发为 1；后台可以继续处理队列中的学生作业对象。

| 层级 | 建议目标 | 说明 |
|---|---:|---|
| 前台教师会话 | 1 | 单教师模式，不设计多教师同时操作同一批次 |
| 后台批改任务 | 4 个/实例 | 4 个学生作业对象可同时进行预处理、OCR 和 DeepSeek 调用；超出部分排队 |
| 待处理队列 | 20 个起步 | 用于吸收班级批量上传的短时峰值；队列长度可配置 |
| 压力测试 | 8 个任务 | 作为超出目标的稳定性测试，不承诺满足 60 秒耗时目标 |
| DeepSeek 请求并发 | 客户端上限 4 | 由本地任务处理器控制，不能直接使用供应商公开上限作为本项目承诺 |

#### 硬件档位

| 档位 | 最低建议 | 用途与边界 |
|---|---|---|
| 功能验证最低 | x86_64 6 核 12 线程 CPU、16 GB RAM、512 GB SSD，预留至少 20 GB 可用空间；无独立 GPU 也可运行 | 单教师、1 个后台任务为主；用于功能开发和小样本验证，不承诺 4 并发和 60 秒目标 |
| 首版目标验收 | x86_64 8 核 16 线程 CPU、32 GB RAM、NVMe SSD，预留至少 50 GB 可用空间；可选 6–8 GB 显存 NVIDIA GPU | 用于 4 并发目标、批量 OCR 和性能验收；GPU 只作为 OCR 加速项，不承担 DeepSeek 模型本地推理 |
| 推荐部署 | x86_64 12 核 24 线程或以上、32–64 GB RAM、NVMe SSD；8 GB 以上 NVIDIA GPU（如采用 GPU OCR） | 用于较大批次、复杂版式和后续扩展；需按实际模型和驱动验证 |

部署系统建议：Windows 10/11 64 位或 Ubuntu 22.04 LTS，Python 3.12；处理器使用 x86_64 架构并满足 PaddlePaddle 的 MKL/指令集要求。Windows 原生可先做标准 CPU 推理验证，高性能 OCR 测试优先放在 WSL2、Docker 或 Linux 环境。

硬件建议是工程基线，不是 PaddleOCR 或 DeepSeek 的官方最低配置。PaddleOCR 官方文档同时提供 CPU 和 NVIDIA GPU 推理路径，GPU 加速需要匹配 CUDA/TensorRT 等环境；Windows 原生可用于标准推理，高性能推理建议使用 WSL2 或 Docker。项目最终以所选 OCR 模型、操作系统、图片分辨率和实际作业集实测为准。

技术依据： [DeepSeek-V4.1-Flash 更新说明](https://api-docs.deepseek.com/news/news260910/)、[DeepSeek 模型与定价](https://api-docs.deepseek.com/quick_start/pricing/)、[PaddleOCR 快速开始](https://www.paddleocr.ai/main/en/quick_start.html)、[PaddleOCR PP-OCRv5 性能参考](https://www.paddleocr.ai/main/en/version3.x/algorithm/PP-OCRv5/PP-OCRv5.html)。

#### 验证方式

1. 在“首版目标验收”硬件上，以 1、2、4、8 个学生作业对象分别运行批改任务。
2. 每个任务使用代表性语文、数学、英语样本，并覆盖印刷体、手写体、横竖版、分栏和多页合并场景。
3. 记录 OCR 耗时、DeepSeek 调用耗时、端到端耗时、CPU/RAM/GPU 使用率、队列等待、失败重试和人工接管比例。
4. 只有 1、2、4 并发均无数据丢失、状态错乱和任务死锁时，才能确认 4 并发目标；8 并发只用于观察降级行为。

## 12. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 按任务书目标测试单份作业端到端耗时；同时记录平均、P95、最大值、失败重试和并发条件 |
| 并发 | 以 4 个学生作业对象/实例作为首版目标；在 1、2、4、8 并发下测试队列、状态一致性和资源占用 |
| 部署硬件 | 功能验证最低 6 核 12 线程、16 GB RAM、512 GB SSD；首版目标验收建议 8 核 16 线程、32 GB RAM、NVMe SSD；GPU 为可选 OCR 加速 |
| 可靠性 | 任务可查询状态；单页或单题失败不应使整批结果丢失；支持部分重跑 |
| 安全与隐私 | HTTPS 传输、敏感信息脱敏、数据库/文件保护、本地化部署选项、访问权限和数据删除策略 |
| 合规 | AI 生成评分与评语显著标识；使用鼓励性、建设性表达；正式成绩以教师复核为准；使用前取得必要知情同意 |
| 浏览器兼容 | 支持 Chrome、Firefox、Safari、Edge 最新两个版本；按实际版本记录验证结果 |
| 可维护性 | 评分标准、提示词、模型、规则和数据处理版本可追踪；日志不记录不必要的学生敏感信息 |

## 13. 产品评估与验收

### 13.1 功能验收

| 验收域 | 最低检查项 |
|---|---|
| 作业管理 | 创建班级/批次、上传 JPG/PNG/PDF、失败重试、答案与评分标准绑定 |
| OCR | 印刷体与工整手写样本识别；原图/文本对照；位置、页码、置信度和人工修正记录 |
| 评分 | 客观题规则判分；主观题分项评分、证据、扣分原因和评语；异常进入复核 |
| 报告 | 个人和班级统计；未复核标识；错误/薄弱项；支持 PDF 或 Word 导出，字段和排版在最终交付阶段另行验收 |
| 追溯 | 可从最终成绩回溯到题目、答案、OCR、评分标准和复核记录 |

### 13.2 量化评测方案骨架

| 项目 | 需要确定的内容 | 输出 |
|---|---|---|
| 数据集 | 学科、题型、页数、样本量、来源授权、8:1:1 划分 | manifest、标注说明和数据版本 |
| OCR | 字符/文本块准确率、编辑距离、低置信度样本处理 | 分项结果与 bad case 清单 |
| 客观题 | 逐题准确率、错判类型、容错规则 | 混淆明细和错误样例 |
| 主观题 | 人工评分档位、评分人数量、冲突仲裁、一致率算法 | 人机对比结果和误差分析 |
| 性能 | 首版目标硬件、DeepSeek API、1/2/4/8 并发、页数/题数、平均/P95/最大耗时 | 可复现性能报告；确认 4 并发是否达标 |
| 教师体验 | 完成一批作业的操作时间、修改率、异常处理时间 | 任务完成率和操作记录 |

### 13.3 验收判定原则

- 指标报告必须说明数据来源、样本数、计算方法、软件版本、模型版本和硬件环境。
- 不能用 OCR 识别数据集的结果代替完整作业批改结果。
- 不能用模型输出的平均分代替主观题评分档位一致率。
- 性能指标应同时报告平均值和 P95，不能只报告最快的一次结果。
- 失败样本和人工接管比例必须单独统计，不能从分母中随意删除。
