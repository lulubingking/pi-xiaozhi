### 1.1 文档目标

本文件用于指导批小智首版 Web 产品的界面设计、交互设计、前端实现和 UI 验收，覆盖：

## 2. 产品概述

### 2.1 产品定位

批小智是面向国内个人教师的作业批改与复核工作台。它以可复用的评分标准为依据，帮助教师完成整批作业的上传、识别校对、逐题评分、异常处理、教师复核和成绩报告查看。

产品的核心不是让教师“看一眼 AI 分数就结束”，而是让教师能够快速定位需要判断的地方，并且随时回到原图、OCR 文本、评分依据和操作历史进行核查。

### 2.2 产品价值

| 价值 | UI/UX 体现 |
|---|---|
| 批改效率 | 批量上传、后台处理状态、异常优先队列、逐题确认后自动进入下一题 |
| 结果可控 | 原图只读、OCR 文本可校对、AI 结果可修改、评分依据可查看 |
| 评分一致 | 评分标准版本、评分点、分值、示例和模型/规则版本可追溯 |
| 班级洞察 | 正式成绩、AI 初评参考、得分分布、按题目失分和薄弱项分开呈现 |
| 数据合规 | 调用模型前脱敏，AI 内容显著标识，正式成绩必须由教师复核 |

### 2.3 首版范围

首版 UI/UX 覆盖：

- 语文、数学、英语三类学科；
- 三类学科的常规题型；具体题型清单待数据集阶段固化；
- JPG、PNG、PDF 批量上传；
- 批次、班级和学生标识维护；
- OCR 原图与文本对照校对；
- 多页作业的学生归属、页序和跨页答案处理；
- 客观题规则判分；
- 主观题按评分点生成 AI 初评建议、证据、扣分原因和评语；
- 异常标注、重试、部分重跑和教师复核；
- 个人成绩和班级统计报告查看；
- 单教师运行配置、文件存储和数据保留说明。

首版不包含：

- 学校级权限、多教师协作和细粒度角色权限；
- 学生端自主订正；
- LMS 集成；
- 超出常规题型的复杂开放题评分；
- PDF 或 Word 格式的正式报告导出实现。

## 3. 用户与使用场景

### 3.1 用户角色

| 用户 | 主要目标 | 关键任务 | UI 关注点 |
|---|---|---|---|
| 个人教师（核心） | 提高日常批改效率并保留判断权 | 创建班级、创建批次、上传、校对、批改、复核、看报告 | 异常优先、状态明确、少重复操作、可回溯 |
| 教研或备课组教师（次要） | 复用评分标准和比较班级表现 | 维护标准、查看统计、参与复核 | 版本、适用学科、统计口径和历史记录清晰 |
| 单教师运行配置 | 维护当前运行环境 | 设置教师姓名、模型接口、存储和数据保留 | 不暴露 API Key，不虚假显示连接成功 |

首版只有单教师模式。UI 不应出现“邀请成员”“协作编辑”“管理员审批”等超出范围的入口。

### 3.2 典型用户旅程

```text
登录
  ↓
工作台查看待处理任务
  ↓
维护班级与学生
  ↓
创建作业批次并录入参考答案/评分标准
  ↓
选择当前批次并批量上传 JPG / PNG / PDF
  ↓
逐页确认学生归属、页序和答案
  ↓
运行客观题规则判分与主观题 AI 初评
  ↓
异常优先进入教师复核队列
  ↓
查看原图、OCR、评分依据和 AI 建议
  ↓
保存待复核或确认教师结果
  ↓
查看正式成绩报告或 AI 初评参考
```

### 3.3 设计目标

| 目标 | 设计要求 |
|---|---|
| 让教师知道下一步做什么 | 每个批次状态都要对应一个明确的主操作 |
| 让教师快速处理异常 | 工作台和复核队列按异常、低置信度、失败和未确认项优先展示 |
| 防止误把 AI 当正式成绩 | AI 建议、待复核、教师已确认采用不同状态标签和说明 |
| 防止数据错配 | 批次、班级、学生、文件、页码和题目上下文始终同时显示 |
| 防止不可恢复误操作 | 删除、重跑、离开未保存内容和修改已复核结果前给出解释和确认 |

## 4. 信息架构与导航

### 4.1 一级导航

| 导航 | 页面职责 | 进入条件 | 主要出口 |
|---|---|---|---|
| 工作台 | 待处理任务、批改进度、异常提醒、最近批次 | 已登录 | 进入批次、OCR、智能批改、报告 |
| 作业管理 | 班级、学生、作业批次、上传记录 | 已登录 | 创建批次、上传、OCR |
| 智能批改 | 题目队列、AI 初评和教师复核 | 已登录，选择批次 | OCR、历史、报告 |
| 评分标准 | 评分标准模板、评分点、示例、版本 | 已登录 | 创建/编辑标准、批次配置 |
| 批改报告 | 正式成绩、AI 初评参考、班级统计、失分 | 已登录，选择批次 | 逐题结果、智能批改 |
| 设置 | 单教师姓名、模型接口、存储、数据保留 | 已登录 | 保存设置、隐私说明 |
| OCR 校对 | 特定批次内的处理步骤，不作为独立脱离批次的入口 | 已登录且已有批次文件 | 作业管理、智能批改 |

### 4.2 导航结构

```text
登录页
└── 应用工作区
    ├── 侧边栏
    │   ├── 工作台
    │   ├── 作业管理
    │   ├── 智能批改
    │   ├── 评分标准
    │   ├── 批改报告
    │   └── 设置
    ├── 顶部栏
    │   ├── 移动端导航按钮
    │   ├── 面包屑
    │   └── 批次/班级/学生搜索
    └── 主内容区
        └── 当前页面及批次上下文
```

### 4.3 批次上下文规则

1. OCR 校对必须从具体上传批次进入。
2. 智能批改和批改报告必须显示当前批次、班级和学科。
3. 在批次上下文内切换学生、文件或题目时，必须保留当前批次。
4. 从报告查看逐题结果时，应回到对应学生和题目，而不是重新回到首页。
5. 浏览器刷新后恢复当前页面、批次、文件/页面、学生、题目和报告口径。
6. 返回上一页时保留筛选、滚动位置和未提交输入；如果无法保留，应在离开前提示。

### 4.4 推荐路由形态

以下为实现建议，实际路由命名可由前端工程确定：

| 页面 | 推荐路径 |
|---|---|
| 工作台 | `/workbench` |
| 作业管理 | `/assignments` |
| 批次编辑 | `/assignments/new`、`/assignments/:batchId/edit` |
| 批次上传 | `/assignments/:batchId/upload` |
| OCR 校对 | `/assignments/:batchId/ocr?pageId=...` |
| 智能批改 | `/grading?batchId=...&studentId=...&questionId=...` |
| 评分标准 | `/rubrics` |
| 批改报告 | `/reports?batchId=...&mode=reviewed` |
| 设置 | `/settings` |

推荐路由用于支持刷新、浏览器后退、分享内部定位链接和错误恢复；具体 URL 不是 PRD 已确认的接口约束。

## 5. 核心业务流程与状态

### 5.1 批次流程

```text
草稿
  → 上传中
  → 待识别
  → 识别中
  → 待校对
  → 待批改
  → 批改中
  → 待复核
  → 已复核

识别中 / 批改中
  └── 部分失败 / 需处理 → 重试或人工处理 → 返回主流程
```

### 5.2 单份学生作业流程

```text
待归属
  → 已归属
  → OCR 待校对
  → 评分待复核
  → 异常待处理
  → 教师已确认
```

### 5.3 状态展示规范

| 状态 | 标签文案 | 视觉 | 主操作 | 说明 |
|---|---|---|---|---|
| 草稿 | 草稿 | 中性灰/蓝 | 编辑批次 | 允许继续补充配置 |
| 待上传 | 待上传 | 橙色提示 | 上传作业 | 批次配置已保存但没有文件 |
| 上传中 | 上传中 | 蓝色+进度 | 查看上传进度 | 禁止重复提交同一批上传动作 |
| 待识别 | 待识别 | 蓝色提示 | 开始识别 | 已有文件，等待处理 |
| 识别中 | 识别中 | 蓝色加载 | 查看处理进度 | 显示已完成/总页数、预计等待说明或队列位置 |
| 待校对 | 待校对 | 橙色提示 | 进入 OCR 校对 | 有未确认归属、页序或答案 |
| 待批改 | 待批改 | 蓝色提示 | 运行初评 | 配置和校对已满足要求 |
| 批改中 | 批改中 | 蓝色加载 | 查看队列 | 显示规则评分/模型调用的处理进度 |
| 待复核 | 待复核 | 橙色提示 | 进入复核队列 | AI 初评存在但未正式生效 |
| 部分失败 | 部分失败 | 红/橙色提示 | 查看失败项 | 成功项保留，失败项单独重试 |
| 已复核 | 已复核 | 绿色 | 查看报告 | 整份作业全部题目已确认且未失效 |
| 结果失效 | 待重批 | 橙色警告 | 重跑受影响题目 | OCR 或评分标准已修改 |
| 空数据 | 暂无数据 | 中性空状态 | 创建/上传/筛选 | 必须给出下一步操作 |

颜色不能作为唯一信息来源。每个状态必须同时有文字，重要状态配合语义图标或说明。

### 5.4 结果控制原则

1. OCR 失败不等于空题。
2. 相似度提示不等于抄袭结论。
3. AI 评分只能标记为“建议/待复核”。
4. 教师确认后，结果才进入正式成绩。
5. 评分标准或 OCR 文本修改后，只重新计算受影响题目及其汇总。
6. 原始图片/PDF 和原始 OCR 结果只读保存，教师修改形成新版本。
7. 任何得分都必须能回溯到学生、题目、评分标准版本和规则/模型版本。

## 6. 设计原则

### 6.1 教师控制优先

主按钮的含义必须是“继续处理、保存、确认或重试”，不能使用模糊的“AI 一键完成”作为默认操作。AI 结果旁始终保留查看依据和人工修改路径。

### 6.2 证据链优先

评分页面的核心信息顺序为：

```text
学生作答 → OCR 文本 → 参考答案/评分标准 → AI 建议 → 教师结论
```

任何结果卡片都不应只展示一个分数而隐藏来源。

### 6.3 异常优先

工作台和复核队列首先展示低置信度、疑似空题、缺页、题目未匹配、异常分数、模型失败和学生归属冲突。

### 6.4 批次上下文优先

所有处理页面均显示：批次名称、班级、学科、文件/页面、学生和题号。禁止在没有批次上下文的情况下单独进入 OCR 处理。

### 6.5 清晰而克制

采用浅色、专业、数据工作台风格。视觉重点放在任务状态、异常和证据，不使用大面积装饰性渐变、复杂玻璃效果或与批改无关的动效。

### 6.6 渐进式披露

批次创建先完成最少必要配置；评分点详情、版本历史、模型信息和原始字段在需要时展开或通过侧边区域/弹窗查看。

### 6.7 不虚构能力

当前原型的模拟数据、演示账号、模拟评分和本地存储提示必须带有边界说明。正式产品 UI 不得显示未经验证的 OCR 准确率、模型连接成功或自动识别成功。

## 7. 视觉设计系统

### 7.1 视觉基线

当前 `prototype.html` 使用浅色工作台作为视觉基线：浅灰背景、白色卡片、信任蓝导航、深橙色主操作、细边框和轻阴影。正式产品应将这些颜色抽象为语义 token，避免在组件内散落硬编码颜色。

首版不强制提供深色模式。若后续增加深色模式，必须单独验证文字、边框、状态和弹窗遮罩的对比度，不能简单反转颜色。

### 7.2 颜色 Token

| Token | 建议值 | 用途 |
|---|---|---|
| `--color-primary` | `#2563EB` | 主导航、链接、次级强调、焦点环 |
| `--color-primary-soft` | `#EFF6FF` | 当前导航、信息提示、选中背景 |
| `--color-accent` | `#C2410C` | 每个页面唯一主 CTA、确认性操作 |
| `--color-background` | `#F7F9FC` | 页面背景 |
| `--color-surface` | `#FFFFFF` | 卡片、表单、弹窗 |
| `--color-foreground` | `#1E293B` | 标题、正文、主要数据 |
| `--color-muted-foreground` | `#52627A` | 辅助说明、次要信息 |
| `--color-border` | `#DCE4EF` | 卡片、表格、输入框边界 |
| `--color-info` | `#2563EB` | 信息、处理中、可继续 |
| `--color-success` | `#166534` | 已复核、成功 |
| `--color-success-soft` | `#ECFDF3` | 成功状态背景 |
| `--color-warning` | `#9A3412` | 待复核、低置信度、待处理 |
| `--color-warning-soft` | `#FFF7ED` | 警告状态背景 |
| `--color-danger` | `#B91C1C` | 失败、危险、阻止操作 |
| `--color-danger-soft` | `#FFF1F2` | 错误背景 |
| `--color-scrim` | `rgba(20,32,52,.44)` | 弹窗遮罩 |

要求：

- 正文颜色与背景保持至少 4.5:1 对比度；
- 重要图标、输入边界和焦点状态至少具备 3:1 的非文本对比度；
- 成功、警告和失败状态同时展示文字，不得只使用绿/黄/红；
- 颜色只在语义 token 中定义，页面组件不直接写入未登记的色值。

### 7.3 字体与字号

| Token | 桌面端 | 移动端 | 用途 |
|---|---:|---:|---|
| `text-xs` | 12px | 12px | 时间、版本、辅助元数据，不用于长正文 |
| `text-sm` | 13px | 14px | 标签、表格辅助信息 |
| `text-body` | 14px | 16px | 正文、表单内容 |
| `text-body-lg` | 16px | 16px | 重点说明、长文本 |
| `text-h3` | 15px | 16px | 卡片标题 |
| `text-h2` | 19px | 18px | 区块标题 |
| `text-h1` | 30px | 26px | 页面标题 |
| `text-metric` | 29px | 24px | 统计数字 |

推荐字体栈：

```css
font-family: "Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", Arial, sans-serif;
```

正文行高为 1.5–1.75。长说明文字在桌面端控制在约 60–75 个字符一行，移动端控制在约 35–60 个字符一行。数字列使用等宽数字或 `font-variant-numeric: tabular-nums`，避免进度和分数变化造成布局跳动。

### 7.4 间距与布局

采用 4/8px 节奏：

| Token | 值 | 用途 |
|---|---:|---|
| `space-1` | 4px | 图标与文字的紧邻间距 |
| `space-2` | 8px | 控件内部、标签之间 |
| `space-3` | 12px | 紧凑字段间距 |
| `space-4` | 16px | 卡片内边距、普通区块间距 |
| `space-5` | 20px | 两栏间距、问题卡片间距 |
| `space-6` | 24px | 页面区块内边距 |
| `space-8` | 32px | 页面内容边距 |
| `space-12` | 48px | 大区块分隔 |

桌面端应用壳：

- 侧边栏宽度约 230px；窄桌面约 190px；
- 顶部栏最小高度约 70px；
- 主内容最大宽度约 1500px；
- 页面左右内边距桌面端 32px，平板端 22px，移动端 14–20px；
- 主内容不得被固定侧栏、顶部栏或底部操作栏遮挡。

### 7.5 圆角、边框与阴影

| Token | 建议值 | 用途 |
|---|---|---|
| `radius-sm` | 8px | 输入框、次级按钮 |
| `radius-md` | 10–12px | 卡片、状态标签 |
| `radius-lg` | 16px | 弹窗、登录卡片 |
| `border-default` | 1px solid `--color-border` | 默认边界 |
| `shadow-sm` | `0 1px 2px rgba(23,44,76,.04)` | 卡片轻微层次 |
| `shadow-lg` | `0 24px 80px rgba(16,36,60,.25)` | 弹窗 |

卡片默认依靠背景、边框和间距建立层次，不使用每张卡片不同的阴影。仅可点击卡片才使用悬停反馈，普通信息卡片不应产生“可点击”的错觉。

### 7.6 图标规范

- 使用 SVG 或统一图标库，不使用 Emoji 作为导航、设置、状态或系统操作图标；
- 统一使用线性图标或同一层级内一致的填充风格；
- 图标尺寸使用 `16 / 20 / 24px` token；
- 独立图标按钮必须有可访问名称、状态和提示；
- 装饰性图标设置 `aria-hidden="true"`；
- 图标旁已有可见文字时，图标不重复朗读；
- 图标按钮视觉尺寸可以小于 44px，但可点击区域不得小于 44×44px。

## 8. 通用组件规范

### 8.1 应用壳

**桌面端：** 固定侧边栏 + 顶部栏 + 可滚动主内容。侧边栏显示品牌、六个一级导航和教师复核保护提示。顶部栏显示面包屑和全局搜索。

**移动端：** 侧边栏默认隐藏，通过带 `aria-expanded` 的导航按钮打开；打开时显示遮罩，焦点进入侧边栏，关闭后焦点回到触发按钮。

### 8.2 页面标题区

每个页面包含：

1. 小型页面标识/面包屑；
2. 唯一页面主标题；
3. 一句解释页面任务和数据口径的说明；
4. 右侧最多一个主 CTA，其余为次级操作。

主标题不使用纯营销文案。例：使用“原图与答案校对”，不使用“让 AI 帮你轻松搞定所有作业”。

### 8.3 按钮

| 类型 | 样式 | 使用场景 |
|---|---|---|
| Primary | 深橙背景、白色文字 | 页面唯一主操作，如创建、确认、运行 |
| Secondary | 白底、边框或蓝色文字 | 保存草稿、查看、返回、筛选 |
| Link | 无边框蓝色文字 | 表格行内查看、跳转历史 |
| Danger | 红色文字或红边框 | 删除、停用、放弃、重置等危险动作 |
| Disabled | 降低对比度并显示原因 | 依赖条件未满足时使用 |

所有按钮必须：

- 有明确动词；
- 提供悬停、按下、聚焦、禁用状态；
- 异步操作期间禁用重复提交并显示处理中；
- 点击后在 100ms 内给出反馈；
- 主要触控目标不小于 44×44px；
- 不用颜色变化单独表达成功或失败。

### 8.4 状态标签

状态标签格式为“语义图标（可选）+ 文字”，不显示只含颜色的小圆点。示例：

```text
✓ 已复核
! 待复核
! 部分失败
↻ 处理中
```

AI 相关状态使用完整文案：

- `AI 生成，教师复核后生效`；
- `AI 初评参考，非正式成绩`；
- `模拟主观评分，不代表真实模型判断`（仅原型）；
- `结果已失效，请重新校对并重跑`。

### 8.5 表单字段

- 每个字段有可见标签，不以 placeholder 代替标签；
- 必填字段使用“*”并在表单说明中解释；
- 错误显示在字段附近，同时在表单顶部提供可聚焦的错误汇总；
- 多个错误时错误汇总链接到每个字段；
- 复杂字段提供持久辅助说明；
- 默认在失焦或提交后校验，不在用户每次输入时打断；
- 失效/只读/禁用三种状态视觉和语义不同；
- 退出未保存表单时二次确认，支持关闭按钮、Escape 和焦点恢复。

### 8.6 弹窗与抽屉

- 适用于创建批次、班级管理、评分标准、上传记录、PDF 页数、历史记录等局部任务；
- 不用弹窗承载主导航或多步骤核心工作流；
- 弹窗有标题、关闭按钮、明确的取消和保存动作；
- 打开时记录触发元素，关闭后恢复焦点；
- 支持 Escape 关闭；有未保存内容时先确认；
- 内容超过视口时标题和操作栏保持可见，正文独立滚动；
- 弹窗遮罩只用于隔离背景，不承担装饰作用。

### 8.7 Toast 与全局反馈

Toast 只用于短暂、非阻塞的完成反馈，例如“校对草稿已保存”。

- 显示 3–5 秒后自动消失；
- 使用 `role="status"` 或 `aria-live="polite"`，不抢夺焦点；
- 失败和需要用户操作的错误不能只放 Toast，必须在相关区域保留错误说明和恢复操作；
- 同一时刻只显示一条最重要的消息，避免连续弹出覆盖。

### 8.8 空状态

空状态必须包含：当前没有什么、为什么没有、下一步能做什么。

| 场景 | 文案示例 | 操作 |
|---|---|---|
| 无班级 | 尚未创建班级 | 管理班级与学生 |
| 无批次 | 暂无批次 | 创建批次 |
| 无上传文件 | 尚未上传文件 | 选择批次并上传 |
| 无评分标准 | 暂无评分标准 | 创建评分标准 |
| 无正式报告 | 暂无符合当前口径的完整成绩 | 去教师复核 |
| 筛选无结果 | 没有符合筛选条件的批次 | 重置筛选 |

### 8.9 错误与恢复

错误文案统一使用“原因 + 影响 + 下一步”结构：

```text
PDF 页数与当前记录不一致，超出页数的页面已有答案，不能直接删除。
请保留已有页面，或先清除相关校对内容后再调整页数。
```

不能使用“出错了”“Invalid input”“保存成功但实际没有保存”等模糊或虚假的反馈。

### 字段与交互

| 元素 | 规则 |
|---|---|
| 账号 | `email` 类型，支持浏览器自动填充；登录失败保留输入内容 |

- `[原型现状]` 使用本地模拟账号，不连接真实认证服务；
- `[PRD-P0]` 正式产品需要服务端认证、密码安全存储、会话过期、失败限制和权限校验；
- 测试账号不能出现在正式产品登录页；
- 不在浏览器 `localStorage` 保存正式密码或可长期复用的认证凭据。

### 验收点

- 账号错误时不清空账号字段；
- 错误区域具备 `role="alert"`；
- Tab 顺序为账号 → 密码 → 保持登录 → 登录；
- 登录按钮聚焦状态清晰；
- 移动端不发生页面级横向溢出。

- 无数据：显示创建批次和管理班级；
- 有草稿：优先显示继续配置；

- 处理中：显示处理中、已完成数量、队列位置和停止/查看入口，不能让页面看起来无响应。

| 删除题目 | 需要确认；已有评分关联时说明历史结果将失效 |

### 页面目标

让教师明确知道文件属于哪个批次，并对每个文件显示独立校验、保存进度和失败原因。

### 线框

```text

student_002.pdf       文件损坏             重新选择文件重试

```

### 交互规则

- 未选择批次时不能选择或提交文件；
- 每个文件独立显示等待、校验、保存、成功、失败和重试状态；
- 单个文件失败不能阻塞同批次其他文件；
- 文件内容与扩展名不一致、文件损坏、大小或数量超限时在文件行显示原因；
- 失败文件只能通过“重新选择文件重试”恢复；
- 完成上传后只进入当前批次 OCR 校对；
- 进入 OCR 按钮在没有成功页面时禁用，并解释原因；
- 大批量文件显示已处理/总数、成功、失败和待处理数量；
- 正式产品按 PRD 的队列策略处理，最多 4 个学生作业对象同时处理，超出进入队列；该数值需以性能测试校准。

### 原型边界

`prototype.html` 当前的单文件 20 MB、单次 50 个文件是测试保护限制，不是 PRD 最终产品指标，UI 文案必须标记为原型限制或由正式产品配置替换。

```text
│                            │ │                                 │
│                            │ │ [ ] 本页包含第1题               │
│                            │ │ 第1题学生作答 [              ] │
│                            │ │ [ ] 已对照原图，确认未作答      │
│                            │ │                                 │
│                            │ │ [ ] 本页包含第2题               │
│                            │ │ 第2题学生作答 [              ] │
│                            │ │                                 │
│                            │ │ [保存校对草稿] [确认本页校对]   │
└──────────────────────────┘ └────────────────────────────────┘
```

### 信息和控件

| 区域 | 内容 |
|---|---|
| 原图区域 | 原始图片/PDF 预览、文件名、原始页码、放大/打开原文件 |
| 文件选择 | 当前批次所有文件/页面、文件状态、页码、学生归属和校对状态 |
| 学生归属 | 班级学生列表、待确认选项、归属依据、归属置信度 |
| 页序 | 学生作业内的连续页序；重复或不连续时阻止确认 |
| 题目区域 | 本页是否包含题目、学生答案、确认空题 |
| OCR 文本块 | 正式 OCR 版本显示文本、位置和置信度；低置信度高亮并可定位原图 |
| 历史 | 查看修改前后值、教师、时间和原因 |

### 校对规则

1. 不能把 OCR 失败自动保存为“空题”。
2. 只有勾选“本页包含”才保存该题答案。
3. 有文本时不能同时勾选“确认未作答”。
4. 确认页时，学生归属必须存在。
5. 页序必须是正整数，且同一学生不能重复。
6. 未确认归属、重复页序、页序不连续和跨页答案冲突时不能进入批改。
7. 同一学生的多页答案按 `page_sequence` 拼接。
8. 修改学生归属、页序或答案后，关联评分结果标记为待重批。
9. 原始文件和原始 OCR 结果只读保存，修改形成新版本。

### 真实 OCR 接入后的增强

- 原图上的文本框与右侧文本块双向定位；
- 低置信度文本块在原图和文本编辑区同步高亮；
- 显示处理版本、置信度、预处理方式和失败原因；
- OCR 失败时提供人工录入、重试和转人工处理；
- PDF 页数和页面拆分由系统读取，保留教师修正入口。

### 当前原型边界

`prototype.html` 当前为人工对照录入，置信度和文本位置为未知；PDF 页数需要人工输入；没有真实方向校正、去噪、版面定位、自动学生归属和自动拆页。以上内容不能在原型验收中当作真实 OCR 能力。

### 9.7 智能批改与教师复核页

### 页面目标

按学生和题目提供复核队列，让教师在一个页面内完成证据核对、分数调整、评语修改和正式确认。

### 桌面线框

```text
评分与教师复核                         [AI生成，教师复核后生效]
所属批次 [八年级英语单元测试] [返回OCR] [运行/补齐初评]

┌复核队列───────────────┐ ┌题目复核详情──────────────────────┐
│ 筛选 [全部/待处理/已复核]│ │ 张同学 · 001 · 第3题              │
│                         │ │ 客观题/规则判分 或 主观题/AI初评   │
│ ! 张同学 · 第3题        │ │ [查看原图/OCR] [历史记录] [仅重跑]  │
│   待复核 11 / 15        │ │                                      │
│ ! 李同学 · 第2题        │ │ 学生作答（按页序拼接）             │
│   OCR低置信度           │ │ [只读答案文本]                       │
│ ✓ 王同学 · 第1题        │ │                                      │
│   已复核 5分             │ │ 参考答案/评分依据                   │
│                         │ │ [答案/评分标准/版本/示例]            │
│                         │ │                                      │
│                         │ │ AI 建议 11 / 15 · 待复核            │
│                         │ │ 证据：...                            │
│                         │ │ 扣分原因：...                         │
│                         │ │                                      │
│                         │ │ 评分点分数 [ ] [ ] [ ]                │
│                         │ │ 评语* [                           ]   │
│                         │ │ 修改原因 [                       ]     │
│                         │ │ [保存待复核] [确认本题并查看下一题]   │
└─────────────────────────┘ └──────────────────────────────────┘
```

### 详情展示顺序

1. 学生、学号/编号、批次、题号和题型；
2. 原图/OCR 快速回看入口；
3. 学生答案；
4. 参考答案、评分标准版本、评分点和示例；
5. AI 建议分、分项分数、引用证据、扣分原因和异常；
6. 教师评分、教师评语和修改原因；
7. 当前状态、复核人、复核时间和历史记录。

### 客观题

- 显示学生答案、参考答案、容错规则版本、匹配结果、得分和判分理由；
- 结果越界时阻止保存并显示原因；
- 教师可以修改分数和评语，修改时必须填写原因；
- 规则判分结果也要经过教师确认后计入正式成绩。

### 主观题

- 按评分点展示分项建议，不只展示总分；
- 每个评分点显示证据、扣分原因和对应分值；
- 显示评分标准名称、版本、模型版本和提示词版本；
- AI 建议不能通过单个“接受全部”按钮直接写入正式成绩；
- 教师可以逐项调整分数、修改评语和填写原因；
- 分项分值合计必须等于题目总分，分数必须在合法范围内。

### 复核动作

| 动作 | 结果 |
|---|---|
| 保存待复核 | 保存教师当前编辑，但不计入正式成绩 |
| 确认本题 | 保存教师结果，标记本题已复核，并自动定位下一条未复核题 |
| 查看原图/OCR | 返回对应批次 OCR 页，并定位到相关文件/页面/题目 |
| 查看历史记录 | 展示修改前后值、教师、时间、原因 |
| 仅重跑本题 | 保留历史，撤销当前复核状态，重新进入待复核；已复核题需二次确认 |
| 返回校对 | 有未保存编辑时先确认放弃或保存 |

### 复核完成条件

只有当前学生整份作业全部题目完成教师复核且没有失效结果，才可以进入正式报告统计。单题已复核不代表整份作业完成。

### 9.8 评分标准知识库

### 页面目标

按学科和题型维护可复用、可版本追踪的评分标准。

### 页面布局

- 顶部显示页面说明和“创建评分标准”主按钮；
- 标准卡片显示名称、学科、题型、版本、评分点摘要、总分和启用状态；
- 每张卡片提供编辑、启用/停用和版本历史；
- 页面底部提供版本校验规则说明。

### 评分标准编辑字段

| 字段 | 规则 |
|---|---|
| 标准名称 | 必填，同一使用场景下保持可识别 |
| 学科 | 语文/数学/英语 |
| 主观题型 | 必填，题型清单以数据集阶段固化 |
| 题目总分 | 大于 0 |
| 评分点与分值 | 每行一个评分点；合计必须等于题目总分 |
| 示例作答 | 可选；可以关联评分点 |
| 状态 | 启用/停用；停用标准不能用于新批次，历史批次继续保留绑定版本 |

### 版本规则

1. 编辑评分标准后版本递增。
2. 旧版本保留历史，不覆盖历史批次的绑定版本。
3. 仅使绑定该版本的受影响题目结果失效。
4. 未受影响的题目不能被无故重跑。
5. 评分点合计、题目总分和批次总分必须分别校验。

### 9.9 批改报告页

### 页面目标

提供可解释的个人成绩和班级分析，严格区分正式成绩和 AI 初评参考。

### 页面结构

```text
班级成绩与薄弱项                 [导出 PDF / Word]
只展示当前批次汇总；未复核结果单独标识。

批次范围 [八年级英语单元测试]   统计口径 [教师已复核 | AI初评参考]
提示：正式成绩口径 / 仅供教师参考，不进入正式成绩

[可统计学生] [平均分] [最高分] [批次满分]

┌成绩分布──────────────────┐ ┌讲评线索────────────────────┐
│ 图表/文本摘要              │ │ 高频错误/薄弱项              │
│ 图例、统计范围、时间       │ │ 按题目查看错误明细           │
└───────────────────────────┘ └───────────────────────────┘

个人成绩单
学生 | 客观题 | 主观题 | 总分 | 状态 | 详情
```

### 统计口径

| 模式 | 统计内容 | 视觉说明 |
|---|---|---|
| 教师已复核 | 当前批次中整份作业全部题目已复核且未失效的学生 | 正式成绩标签 |
| AI 初评参考 | 已生成初评的结果，可含模拟或 AI 建议 | 橙色警告，明确“非正式成绩” |

### 报告数据规则

- 未复核学生显示状态和已复核题数，但不得伪装成完整总分；
- OCR 未确认、页序冲突、结果失效的学生不计入正式成绩；
- 学生答案或评分依据修改后，相关结果退出正式报告，直到重新初评并复核；
- 得分分布必须标明批次范围、统计时间和口径；
- 无数据时显示空状态，不显示空坐标轴或虚构图表；
- 当前未接入知识点标注时，不推断虚构的薄弱知识点。

### 图表规范

- 得分区间使用横向条形图，旁边直接显示人数；
- 图表下方提供文本摘要和可访问的表格/列表替代；
- 图例靠近图表，状态颜色配合文字；
- 移动端简化为分布列表或横向条形图；
- 不使用超过 5 类的饼图；
- 图表加载时显示骨架屏，失败时显示错误和重试；
- 导出功能支持 PDF 或 Word；正式导出实现或当前数据条件未满足时禁用，并解释具体原因和下一步操作。

### 9.10 设置页

### 页面目标

维护单教师运行配置，同时明确模型、存储、隐私和数据保留边界。

### 设置分区

1. **教师配置：** 教师姓名，用于复核记录。
2. **DeepSeek 接口：** 模型调用名 `deepseek-flash`、接口地址、API Key 配置状态和连接测试。
3. **文件与数据：** 文件保存位置、数据保留期限、清理说明。
4. **隐私与脱敏：** 姓名/学号脱敏、恢复映射保存位置、外部 API 数据协议。
5. **运行边界：** 单教师前台交互、后台处理数量、队列长度和正式成绩规则。

### 安全要求

- `[PRD-P0]` 正式产品不得把 API Key 暴露在前端可读存储或日志中；
- API Key 输入框默认掩码，具备显示/隐藏和清除能力；
- 连接测试只在真实后端配置完成后启用；
- 模型未配置、超时、限流、空响应和格式错误要进入可恢复异常流程；
- 调用前对姓名、学号等敏感信息脱敏；
- 原图、PDF、OCR、评分和复核记录的存储、保留、删除策略需可解释；
- 原型可以显示限制说明，但不能模拟真实“连接成功”。

## 10. 学生多页作业归属设计

### 10.1 归属对象

一个学生在一个批次中的多个图片/PDF 页面，必须先归并为一个学生作业对象，再进入 OCR 和批改。

### 10.2 页面需要展示的字段

| 字段 | 页面表现 |
|---|---|
| `student_id` | 当前学生姓名/编号；为空时显示“待人工确认” |
| `assignment_group_id` | 在高级信息或辅助文本中可查看 |
| `source_file_id` | 文件信息和历史中可查看 |
| `page_index` | 原文件页码，只读 |
| `page_sequence` | 学生作业内页序，可编辑 |
| `grouping_confidence` | 自动建议置信度，未知时显示“未知” |
| `grouping_reason` | 文件名、页眉/学号、连续页码或人工指定 |
| `grouping_status` | 建议、已确认、需处理、失败 |
| `confirmed_by/at` | 历史记录展示 |

### 10.3 必须人工确认的时机

- 首次自动归并后；
- 学生标识冲突；
- 页序不连续或重复；
- 同一学生出现多个候选作业对象；
- 系统不能可靠判断页面归属；
- 跨页答案出现空题与有答案冲突。

### 10.4 失败兜底

失败时保留原文件和单页记录，标记为 `needs_review`。教师可以：

- 手动选择学生；
- 调整页序；
- 拆分作业对象；
- 合并作业对象；
- 重试自动识别；
- 暂存草稿。

未确认前不得进入最终评分汇总。

## 11. 交互反馈、异常和边界状态

### 11.1 长任务反馈

所有上传、预处理、OCR、批改和报告生成任务至少支持以下状态：

```text
等待 → 处理中 → 成功
             ├→ 部分失败 → 查看失败项/重试
             └→ 失败 → 查看原因/重试/转人工
```

等待超过 1 秒时使用稳定的骨架或进度反馈；不得使用会导致布局跳动的瞬时文字。正在处理的按钮禁用重复提交，但页面其他不相关区域仍保持可用。

### 11.2 典型异常矩阵

| 异常 | 用户看到什么 | 恢复方式 |
|---|---|---|
| 未创建班级 | 批次配置中提示先创建班级 | 关闭弹窗并进入班级管理 |
| 批次必填项缺失 | 顶部错误汇总+字段错误 | 点击错误项定位并修复 |
| 评分点合计不一致 | 评分标准字段下方显示实际合计和目标合计 | 修改评分点或题目总分 |
| 文件格式错误 | 文件行显示不支持格式 | 重新选择 JPG/PNG/PDF |
| 文件损坏 | 文件行显示文件头/解码失败 | 重新选择文件重试 |
| 单文件超限 | 只阻止当前文件保存 | 压缩或选择其他文件 |
| 文件重复 | 显示同名同内容提示 | 确认是否需要保留 |
| 存储失败 | 顶部固定错误，说明刷新会丢失风险 | 释放空间/重试/联系管理员 |
| 学生归属冲突 | 页面标红并阻止确认 | 手动选择学生和页序 |
| OCR 低置信度 | 原图和文本同时提示低置信度 | 对照原图编辑或重试 |
| 模型超时/限流 | 说明次数、原因和当前状态 | 有限重试，失败后转人工 |
| 分数越界 | 字段附近错误，阻止保存 | 输入合法分数 |
| 修改已复核题 | 显示会撤销复核并保留历史 | 确认后重批 |
| 结果失效 | 旧结果不计入报告 | 校对/更新标准后重跑 |
| 报告无数据 | 显示统计口径和下一步 | 去复核或切换口径 |
| 多标签页冲突 | 顶部停止保存并说明风险 | 复制未保存文字后刷新 |
| 未保存离开 | 确认弹窗 | 保存/放弃/取消离开 |

### 11.3 修改原因规则

以下情况必须填写修改原因：

- 修改 AI 建议分；
- 修改教师已保存的分数或评语；
- 重新确认已经复核的题目；
- 手动处理学生归属冲突；
- 触发已复核题重跑。

修改原因显示在历史记录中，并与修改前后值绑定。

### 11.4 文案原则

- 用“建议、待复核、需要确认”，不用“AI 已判定”；
- 用“相似作答提示”，不用“确定抄袭”；
- 用“未识别/无法确认”，不用“空答案”；
- 用“保存失败，当前修改未持久化”，不用“已保存”；
- 用“部分成功，失败项可重试”，不用“批次完成”。

## 12. 响应式与移动端设计

### 12.1 断点

| 设备 | 宽度 | 设计行为 |
|---|---:|---|
| 小屏手机 | 375px | 作为最小验收宽度，单列布局，导航抽屉，表格卡片化 |
| 移动端 | <768px | 侧边栏抽屉，表单单列，OCR/复核分段显示 |
| 平板/小桌面 | 768–1199px | 窄侧栏或可折叠侧栏，核心两列适度收缩，次要信息折叠 |
| 桌面端 | ≥1200px | 完整侧栏、多列工作台、OCR 原图和编辑区并排 |
| 大桌面 | 1440px | 增加内容留白，不无限拉长文本和表单 |

当前 `prototype.html` 使用约 700px 和 1100px 的 CSS 切换点；正式实现可保留该行为，但必须在 375、768、1024、1440px 实际验收。

### 12.2 移动端通用规则

- 页面级禁止横向溢出；
- 正文最小 16px；
- 触控目标不小于 44×44px，目标间距至少 8px；
- 页面固定操作栏必须预留底部安全空间；
- 侧边栏打开时背景内容不可聚焦；
- 不依赖 hover 触发关键功能；
- 表格转换为卡片，或提供明显的可滚动区域和滚动提示；
- 筛选项按纵向堆叠，状态和主操作优先显示；
- 不强制用户在小屏精确点击原图细线或小图标。

### 12.3 OCR 移动端

移动端不强行把原图和编辑器缩成两个不可读的列，而采用分段/标签页：

```text
[原图] [答案与归属] [题目列表]
```

底部固定“保存草稿 / 确认本页”操作栏，避免用户滚动到页面底部才能提交。原图缩放、页面切换和题目定位必须保留明确的返回路径。

### 12.4 复核移动端

- 默认先显示异常队列；
- 选择题目后进入详情页；
- 原图、评分依据、AI 建议、教师编辑区按纵向顺序排列；
- 主操作固定在底部，但不能遮挡当前输入框或键盘焦点；
- “确认并进入下一题”保留在底部主操作位置；
- 复核队列提供返回列表和当前进度。

### 12.5 横屏与缩放

- 平板横屏使用两列；
- 手机横屏仍保持可读，不锁定屏幕方向；
- 支持浏览器缩放，不使用 `user-scalable=no`；
- 放大文字时不能隐藏按钮、截断错误提示或破坏焦点可见性。

## 13. 可访问性规范

### 13.1 键盘与焦点

- Tab 顺序与视觉阅读顺序一致；
- 所有按钮、链接、输入框、选择框和可操作列表项可键盘访问；
- 保留明显的 `:focus-visible` 焦点环，建议 2–4px；
- 弹窗打开后焦点进入弹窗，关闭后恢复触发元素；
- 错误提交后焦点进入错误汇总，错误汇总链接到字段；
- 页面切换后焦点移动到主内容标题或主区域；
- 不把焦点放到隐藏的移动侧边栏中；
- 拖拽和手势交互必须提供按钮或键盘替代。

### 13.2 语义与读屏

- 使用真实的 `button`、`form`、`label`、`table`、`dialog` 和标题层级；
- 图标按钮提供 `aria-label`；
- 装饰图标使用 `aria-hidden="true"`；
- 当前导航使用 `aria-current="page"`；
- 队列筛选使用选中状态，展开/折叠控件暴露 `aria-expanded`；
- Toast 使用 polite live region；严重错误使用 alert；
- 图表提供文本摘要和表格替代；
- 状态不只依赖颜色，读屏能获得完整状态文案。

### 13.3 表单和错误

- 每个字段有可见标签和唯一 ID；
- 错误字段设置 `aria-invalid="true"`；
- 使用 `aria-describedby` 关联辅助说明和错误说明；
- 多错误表单保留字段内错误，并在顶部提供可聚焦汇总；
- 错误描述原因和修复动作；
- 失败后保留用户已填写内容，避免整页重置。

### 13.4 动效

- 动效只表达状态变化、层级关系或操作反馈；
- 主要使用 opacity/transform，避免动画 width/height 导致布局抖动；
- 进入/退出采用不同速度，退出略快；
- 处理中使用稳定骨架或进度，不连续闪烁；
- 支持 `prefers-reduced-motion: reduce`，减少非必要过渡和滚动动画；
- 动效不能阻塞用户输入或依赖动画结束事件完成业务逻辑。

## 14. 性能与数据安全体验

### 14.1 性能反馈

- 图片/PDF 预览预留宽高，避免内容跳动；
- 非首屏重内容按需加载；
- 50 条以上列表考虑虚拟化或分页；
- 高频搜索、窗口调整和滚动事件使用 debounce/throttle；
- 上传、OCR 和评分任务显示稳定的阶段、进度和失败恢复；
- 原图预览只生成必要的对象 URL，页面离开时释放；
- 不把“页面加载完成”误显示为“AI 评分完成”。

### 14.2 数据安全展示

- 原图/PDF、原始 OCR、校对版本、评分结果和复核记录的关系可追溯；
- 原始内容标记为只读，教师修正显示为新版本；
- 学生敏感标识在需要外部模型调用前脱敏；
- UI 明确提示外部模型调用可能影响隐私、费用和延迟；
- 不在日志、Toast 或错误信息中输出不必要的姓名、学号和作业原文；
- 正式产品不依赖 `localStorage`/`IndexedDB` 作为唯一备份；
- 数据删除和保留策略必须在设置页可解释，并在真正执行前确认。

### 14.3 并发与队列展示

PRD 建议单实例同时处理 4 个学生作业对象，超出部分进入队列，队列起步长度建议为 20。UI 应展示：

- 正在处理数量；
- 排队数量；
- 当前任务阶段；
- 单页/单题失败数量；
- 重试次数和转人工状态。

这些是产品建议和验收基线，不应在未完成性能测试前显示为“已达标”。

## 18. UI/UX 验收清单

### 18.1 视觉

- [ ] 页面使用统一的颜色、字号、间距、圆角和阴影 token；
- [ ] 不使用 Emoji 作为结构性图标；
- [ ] 所有图标来自一致的 SVG/图标系统；
- [ ] 主按钮在单个页面中只有一个最重要的视觉层级；
- [ ] AI 结果和正式成绩的视觉状态明显不同；
- [ ] 正文和状态文字具备足够对比度；
- [ ] 普通卡片不会误导用户以为可点击。

### 18.2 交互

- [ ] 所有异步操作有等待、处理中、成功、部分失败和失败状态；
- [ ] 异步按钮期间不能重复提交；
- [ ] 失败项提供具体恢复操作；
- [ ] 删除、重跑、放弃编辑和修改已复核结果需要确认；
- [ ] 表单错误在字段附近显示，同时有可聚焦错误汇总；
- [ ] Toast 不承担唯一错误反馈；
- [ ] 返回、刷新和浏览器后退不丢失批次上下文；
- [ ] 报告可以回到对应学生和题目。

### 18.3 响应式

- [ ] 375px 无页面级横向溢出；
- [ ] 768px 适配平板布局；
- [ ] 1024px 适配窄桌面/平板横屏；
- [ ] 1440px 内容不无限拉伸；
- [ ] OCR 和复核在移动端采用分段或单列布局；
- [ ] 表格在移动端转卡片或有可操作横向滚动；
- [ ] 固定操作栏不遮挡输入框、错误和焦点；
- [ ] 放大文字后仍能提交表单。

### 18.4 可访问性

- [ ] 键盘可以访问所有核心流程；
- [ ] 焦点环可见，页面切换后焦点位置合理；
- [ ] 弹窗支持 Escape、焦点圈定和关闭后焦点恢复；
- [ ] 图标按钮有 accessible name；
- [ ] 表单字段有 label、helper text 和错误关联；
- [ ] 颜色不是唯一状态表达；
- [ ] 图表有文本摘要/表格替代；
- [ ] 支持 `prefers-reduced-motion`；
- [ ] 错误汇总可被读屏识别；
- [ ] 隐藏导航不会进入键盘焦点序列。

### 18.5 业务一致性

- [ ] 上传必须先选择批次；
- [ ] 文件失败不影响同批次其他文件；
- [ ] OCR 未确认的页面不能进入批改；
- [ ] 重复页序、缺页和跨页答案冲突会阻止批改；
- [ ] 评分点合计、题目总分和批次总分均校验；
- [ ] AI 结果在教师复核前不进入正式成绩；
- [ ] 结果失效后正式报告不再统计旧结果；
- [ ] 报告明确标记正式口径和 AI 初评口径；
- [ ] 原始文件和原始 OCR 不被覆盖；
- [ ] 所有修改保留人员、时间、前后值和原因。

### 18.6 数据与安全

- [ ] 正式认证不依赖原型模拟账号；
- [ ] API Key 不保存在前端明文存储；
- [ ] 外部模型调用前显示脱敏和隐私说明；
- [ ] 存储失败不显示虚假成功；
- [ ] 多标签页冲突会阻止旧页面覆盖新数据；
- [ ] 数据清理、保留和删除操作有确认和结果反馈；
- [ ] 日志和错误信息不暴露不必要的学生敏感信息。

## 20. 交付结论

本 UI/UX 方案以教师复核工作台为中心，围绕“批次上下文、原图证据、评分依据、AI 建议、教师确认、正式报告”建立完整体验闭环。

当前 `prototype.html` 已能验证本地的主要操作路径和数据保护规则，但不能证明真实 OCR、真实模型评分、自动归属、后端持久化或量化指标达标。后续实现应优先把原型已经验证的交互保持住，再补充真实处理状态、失败恢复、服务端安全和移动端专项验收。
