# 批小智 RAG 语料库索引与构建说明

## 1. 语料目标

本目录服务于“AI自动批改作业智能体—批小智”的技术问答、实训辅导、接口查询、部署排障和验收解释。语料只覆盖当前交付包与当前项目源码能支持的内容，不把泛化知识或未验证实验结果伪装成项目事实。

## 2. 文件分层

| 文件 | 用途 |
|---|---|
| `00-SKILL.md` | 实训文档生成规则，来自当前项目根目录 `SKILL.md` |
| `01`—`18` | 按参考交付包要求拆分的主题语料 |
| `提示词.md` | 构建 RAG 助手时使用的角色、边界、引用和拒答规则 |
| 本文件 | 索引、切片、元数据和验收约束 |

## 3. 建议元数据

每个 chunk 建议携带：

```json
{
  "project": "AI自动批改作业智能体-批小智",
  "source_file": "05.RAG语料/14-API接口使用语料库.md",
  "section": "认证接口",
  "chunk_id": "rag-14-auth-001",
  "source_type": "code|doc|handoff|test",
  "verified": true,
  "risk_level": "low|medium|high",
  "updated_at": "2026-09-20"
}
```

## 4. 切片规则

- 按标题、一个业务概念或一个接口分块，建议 300—800 中文字；代码块与其解释保持在同一 chunk。
- 不跨越“事实 / 推理 / 风险”边界拼接。
- 端点路径、请求方法、源文件位置必须整体保留。
- 长文档先按二级标题切分，再按段落合并；不要把整份 HANDOFF 当作单个向量。
- 版本或日期变化时，为旧 chunk 标记过期，不静默覆盖证据。

## 5. 引用规则

回答必须引用语料文件和小节，例如 `[14-API接口使用语料库.md#认证接口]`。如果事实来自源代码，应继续给出代码路径；如果只是 PRD 目标或合理推理，必须标注“设计目标”或“推理”。

## 6. 安全规则

- 不索引有效 API Key、证书私钥、个人隐私、真实学生作业图片或本地数据库文件。
- `question_paper` 与 `student_work` 必须分开描述，避免上传和清理建议误删题目卷或学生证据。
- 不根据 RAG 内容执行删除、批量导出、密钥轮换或生产发布；这类操作必须由用户明确授权并二次核对路径。

## 7. 质量验收

至少检查：文件数量、标题可检索性、接口路径与源码一致、引用可定位、秘密扫描无有效密钥、回答能区分自动化检查和真实 OCR—评分—复核验收。当前交付包已提供项目源码和文档，但真实供应商模型链路仍需按样本与配置单独验收。
