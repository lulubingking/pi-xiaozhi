# 16 错误处理方案

## 前端错误

网络、认证、校验、上传和异步任务错误应显示可理解信息，并保留重试或返回路径；不要吞掉异常或只显示“失败”。检查 `src/api/client.ts` 和 `src/App.tsx`。

## 后端错误

按认证失败、资源不存在、权限不足、输入非法、任务失败、模型供应商错误和文件生命周期冲突分类。错误 detail 不应泄露密钥、堆栈、绝对隐私路径或学生答案原文。

## 数据与任务错误

SQLite 锁先检查重复 worker 和事务范围；OCR/评分失败先保留任务、输入文件和历史，再按接口支持安全重试；报告不一致时核对评分版本、复核修改和导出时间。

## 证据定位

查看 `backend/app/api/errors.py`、各 API 的异常处理、`ocr_worker.py`、`grading_worker.py` 和 `report_export_worker.py`。

## 风险

错误恢复不是无条件重试；重复写入、重复扣费、覆盖人工修改和删除证据都需要幂等检查和人工确认。
