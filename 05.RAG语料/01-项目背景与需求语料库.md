# 01 项目背景与需求

## 可回答问题

批小智解决什么问题？用户是谁？主流程有哪些节点？哪些内容不应被宣称为已完成？

## 事实内容

批小智面向教师作业批改场景，将班级、学生、作业批次、题目卷、学生作业文件、OCR 结果、题目分组、评分任务、教师复核项和报告导出组织成一条可追踪工作流。主流程是：教师登录 → 管理班级和学生 → 创建批次 → 上传题目卷与学生作业 → OCR/分组 → 评分 → 教师复核 → 报告/导出。

题目卷和学生作业必须保持角色区分。低置信度识别、错题分组和主观题评分需要教师确认或复核。API Key 只允许运行时使用，不应进入前端、SQLite、日志、源码或交付包。

## 证据定位

- `HANDOFF.md`：产品边界、工作流和非目标。
- `批小智_PRD_v1.0.0.md`：需求与验收目标。
- `src/App.tsx`：前端工作流视图。
- `backend/app/api`：后端能力入口。

## 验证与边界

前端构建、后端编译、单元测试和 API smoke 不能替代真实 OCR—评分—复核—报告验收。真实准确率、生产部署状态和供应商可用性必须以带人工真值的样本记录为准。
