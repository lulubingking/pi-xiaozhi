# 02 系统架构与技术选型

## 事实内容

前端是 React、TypeScript、Vite，入口位于 `src/main.tsx`，主工作流组件位于 `src/App.tsx`，请求封装位于 `src/api/client.ts`。后端是 FastAPI，应用入口位于 `backend/app/main.py`，路由位于 `backend/app/api`，模型位于 `backend/app/models.py`，schema 位于 `backend/app/schemas.py`，数据库会话位于 `backend/app/db/session.py`。

SQLite 适用于当前单机、本地交付与演示边界；Alembic 负责迁移，OCR 和评分由独立 worker/workflow 处理。该架构强调任务状态、教师确认和本地数据可控，不等于已具备多副本生产部署能力。

## 技术选择理由

- React/TypeScript：适合复杂表单、表格、抽屉和多状态工作流。
- FastAPI/Pydantic：适合按 API schema 约束上传、任务、评分和报告接口。
- SQLAlchemy/SQLite：便于本地单机数据持久化与快速验收。
- Alembic：让数据库结构变化可记录、可重复执行。

## 证据定位

查看 `package.json`、`vite.config.ts`、`backend/requirements.txt`、`backend/app/main.py` 和 `backend/migrations`。

## 风险

SQLite 写入并发、长任务 worker 唯一性、模型依赖和大文件存储是扩展到生产时的主要边界。不要仅凭依赖列表宣称已完成高并发或多机部署。
